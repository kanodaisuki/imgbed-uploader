# T2 方案设计：上传客户端

- 状态：草稿（待评审）
- 对应任务：[`../plans/PLAN.md`](../plans/PLAN.md) T2（1d）
- 前置：T1（config / secrets）。验收映射：验收 8（400 错误透传），并为 T3/T6/T7/T9 提供上传原语

## 1. 范围

`client.ts`：multipart 上传 `POST {serverUrl}/upload`、Query 参数映射、鉴权、响应解析与 URL 优先级（4.3）、错误映射与超时（4.9）。单发无状态，不含并发/重试编排（归 T6）、不含 `testConnection` 业务（归 T3，本任务提供其所需原语）。

## 2. 方案与取舍

### 2.1 HTTP 栈：内置 `fetch` + `FormData` + `Blob`，零新依赖

VS Code 1.146 扩展宿主（Node 20+）自带三件套；T0 spike 的 `extension.js` 已用同一栈对 mock 图床完成真实上传（含中文字节流），可行性已验证。

- ❌ 被否：`axios` + `form-data`（MdImgUpload 的栈）——为 fetch 原生能力引入 2 个运行时依赖，违背 PLAN 依赖策略

### 2.2 Query 参数映射：固定参数恒传，可选参数空则省略

| 参数 | 规则 |
| --- | --- |
| `responseFormat=object`、`returnFormat=full` | 恒传（需求 2 固定项） |
| `uploadChannel`、`uploadNameType`、`serverCompress`、`autoRetry` | 恒传（用户有显式默认值的设置，所见即所得） |
| `channelName`、`uploadFolder`、`expire` | 非空才传（空串交给服务端默认语义，避免空值歧义） |
| `authCode` | `authType=authCode` 且有凭据时传（见 2.3） |

布尔以 `true`/`false` 字符串传递。

### 2.3 鉴权：authType 显式声明，不双写

- `authCode` → query 参数 `authCode=<凭据>`
- `apiToken` → 请求头 `Authorization: Bearer <凭据>`
- `none` → 不携带

凭据由 `secrets.ts` 内部读取（`upload` 签名不带凭据参数，调用方零负担）。❌ 被否：MdImgUpload 的"头 + query 双写"——Token 进 URL 会落服务端访问日志，且 `authType` 设置已显式消歧，双写只剩害处。

### 2.4 响应解析与 URL 优先级（4.3）

`responseFormat=object` 的响应体：`{ src, publicUrl?, expiresAt? }`。响应体缺 `src` 字段或非法 JSON 时抛 `UploadError`（message「上传响应格式异常」）；**不做数组格式回退**——`responseFormat=object` 恒传，仅支持最新版图床（见 §6）。

URL = `customCdn + 文件ID` → `publicUrl` → `src`（已含域名时）或 `serverUrl + src`。

**文件 ID 提取规则**（T1 §2.1 约定的落实）：取 `src` 的 pathname（`new URL(src, serverUrl).pathname` 统一处理相对/绝对），剥掉前导 `/file/` 得文件 ID（含 `uploadFolder` 子路径，如 `videos/a.mp4`）；无 `/file/` 前缀时剥前导 `/` 兜底。拼接前置条件：`customCdn` 已规范化为以 `/` 结尾（T1 normalize）。

### 2.5 错误映射与超时（4.9）

`UploadError extends Error`，携带 `status?`（HTTP 状态码）/ `code?`（响应体 `code` 字段，如 `UPLOAD_FORMAT_NOT_ALLOWED`），`message` 即给用户看的话（简体中文，需求 2）：

| 情形 | message 取值 |
| --- | --- |
| 非 2xx，响应体有 `error` / `message` 字段 | 原样取服务端文本（验收 8）；401/403 在其后追加「请检查认证信息」 |
| 非 2xx，响应体无上述字段 | `HTTP <状态码>` + 响应体片段；401/403 同样追加「请检查认证信息」 |
| 超时（`err.name === 'TimeoutError'`，`AbortSignal.timeout` 抛出） | `上传超时（60 秒）` |
| `serverUrl` 非法（`upload()` 入口 `new URL(cfg.serverUrl)` 预校验失败） | `图床地址无效，请检查 serverUrl 配置` |
| 其他网络错误（含 `fetch` 的 `TypeError`，如 DNS 失败，保留 `cause`） | `上传失败：<cause.message>` |

超时固定 60s（需求 4.2）：`fetch(..., { signal: AbortSignal.timeout(60_000) })`。不做本地重试（`autoRetry` 是服务端渠道切换，客户端重试归 T6 的失败重报）。表中前两行由 `mapError` 落实；超时由 `upload()` 的 catch 按 `err.name === 'TimeoutError'` 分流；`serverUrl` 非法在 `upload()` 入口预校验拦截——**不用 fetch 的 `TypeError` 分流判定 URL 非法**（DNS 失败同样抛 `TypeError`，会误报成配置问题）；其余网络错误兜底，均不进 `mapError`。

## 3. 接口

```ts
// client.ts
export class UploadError extends Error {
  status?: number;
  code?: string;
}

export type UploadResult = { url: string };   // 已按 4.3 优先级解析好的最终 URL

export async function upload(
  file: { name: string; data: Uint8Array },
  cfg: Config,
  opts?: { timeoutMs?: number },   // 仅测试注入超时用（§6），默认 60s
): Promise<UploadResult>;

// 纯函数（供单测）
export function buildQuery(cfg: Config, credential?: string): Record<string, string>;
export function extractFileId(src: string, serverUrl: string): string;
export function resolveUrl(
  res: { src: string; publicUrl?: string },
  cfg: Config,
): string;
export function mapError(status: number, body: string): UploadError;
```

文件 MIME：按扩展名常量映射（png/jpeg/gif/webp/avif/svg/bmp/ico → image/*，仅用于 `Blob` 的 `type`），未知扩展名 `application/octet-stream`。文件名原样进 `FormData`（`Blob` 命名），不转写不 trim。

调用关系：`upload()` 先 `secrets.getCredential()` 再走纯函数 `buildQuery`/`resolveUrl`/`mapError`，故凭据不出现在 `upload` 签名；`mapError` 从响应体提取 `code`（见 2.5）。

## 5. 测试方式

- **单测**（vscode-test 内普通断言）：`buildQuery`（authType 三态、空值省略）、`extractFileId`（相对/绝对/无 `/file/` 前缀/含 uploadFolder 子路径）、`resolveUrl`（customCdn → publicUrl → src 三级优先）、`mapError`（有/无 error 字段、401/403）。
- **集成自测**（自动化，无需人工）：测试内起本地 mock HTTP 服务（Node `http`，随机端口，沿用 spike/mock-server 的响应形态），以 `serverUrl=127.0.0.1:<随机端口>` 调 `upload()`，断言：请求形态（multipart 字段名 `file`、query 参数、authCode query vs Bearer 头）、**文件名保真**（mock 断言收到的 filename 与发送一致，用含中文+空格的文件名如 `图片 1.png`，spike 的 mock 未校验过此项）、200 响应回 URL、400 `UPLOAD_FORMAT_NOT_ALLOWED` 抛 `UploadError` 且 message 为服务端原文、超时路径（mock 延迟 > 60s 不测，用可注入超时参数降到毫秒级验证）。
- **手动**：不做（T3 在真实图床上走查时覆盖）。

## 6. 边界说明

- `expiresAt` 响应字段 v1 忽略（仅文档提示用，无消费方）。
- 仅支持最新版 CloudFlare ImgBed：`responseFormat=object` 恒传且被支持，不兼容旧版的数组响应，不做回退解析（PLAN 风险表已同步口径）。
- `authType=authCode` 但凭据为空时：`upload()` 不做前置检查（4.10 引导归 `ensureReady`，粘贴路径的防御归 T9），不带 `authCode` 直接发请求，服务端 401 按 2.5 映射透传。
- 单文件大小不做本地限制（渠道上限由服务端裁决，409/400 透传）。
- 并发控制、批量重试、进度上报属 T6；本客户端可安全并发调用（无共享可变状态）。
- 超时参数允许测试注入（默认 60s）：`upload(file, cfg, opts?: { timeoutMs?: number })`，仅测试用，不进设置。
