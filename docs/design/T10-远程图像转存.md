## 1. 范围

`download.ts`：`downloadRemote(url)` —— GET 下载远程图像（内存，零临时文件）→ 60s 总时限 → 流式读取并限制 50 MiB → 字节嗅探校验「是不是图片」→ 给出上传文件名，交给 T6 `runUploads` 已有的 `downloadRemote → upload` 链路。**不做**：白名单 hostname 匹配与已回写自识别（T6 §2.2 已落）、回写与报告（T6）、上传（T2）、断点续传/重试策略、`Content-Disposition` 文件名解析、私网/loopback 地址拦截（见 §6 已知风险）、同名文件哈希去重（见 §6）。不改命令清单、设置项与 `package.json`。

## 2. 方案与取舍

### 2.1 纯模块 + 注入替换：策略与传输分层

`download.ts` 不 import `vscode`、不读配置，只负责「URL → 字节 + 上传文件名」。**是否下载**完全由 T6 `planUploads` 决定（转存开关、白名单、自识别）；flow 壳唯一的改动是把 T6 期的抛错桩换成 `downloadRemote` 调用（`io.downloadRemote` 签名 `(url) => Promise<{ name, data }>` 不变，T6 §3 已预留）。并发 3、进度、取消、失败聚合全部继承 `runUploads`——下载与上传在同一个 worker 内串行，转存项与本地项同排队。

- ❌ 被否：把下载写进 `flow.ts` / `planUploads`——纯 IO 单元塞进编排，单测要绕 fake；PLAN §1 模块清单已定 `download.ts`
- ❌ 被否：下载前再判一次白名单/自识别——策略单点（T6 §2.2），两份判断必然漂移
- ❌ 被否：抽通用 HTTP 层与 `client.ts` 共用——两处仅「timeout + try/catch」同形，鉴权、错误映射、文案全不同，参数化后比两份实现更难读
- 不落临时文件：字节直接进内存，`upload({ name, data })` 消费（与 T9 粘贴同口径）

### 2.2 超时与大小上限：60s / 50 MiB

沿用 4.2 的固定 60s（需求只写上传，取同口径，不做成设置）。`AbortSignal.timeout(60_000)` 覆盖建连、响应头与响应体读取（总时限，不是 idle 超时）；超时抛「下载超时（60 秒）」。`opts.timeoutMs` 仅测试注入（与 `client.upload` 同形），文案固定 60 秒，注入时测试只断言前缀。

**捕获范围必须包含响应体读取**：`fetch()` 与 `res.body` 读取放在同一个 try/catch。实测 Node 22 在「响应头已到、body 卡住」时读流会抛 `TimeoutError`；若只包 `fetch()`，`runUploads` 会把英文 `The operation was aborted due to timeout` 当失败文案。两处都映射为「下载超时（60 秒）」。

**body 读取的非超时中断也要收口**：服务端发一半 body 后断连，实测读到 `TypeError: terminated`（`cause.message = other side closed`）。这类异常映射为「下载失败：`<cause.message ?? message>`」（§2.6），不让 `terminated` 之类英文裸文案进报告。

**大小上限 50 MiB（`50 * 1024 * 1024`，解压后字节）**：不用 `arrayBuffer()` 一次性读入，改为 `res.body.getReader()` 流式累计；超过上限立即 `reader.cancel()` 并抛「远程图像过大（超过 50 MB）」。`Content-Length` 大于上限时可在读 body 前直接失败（早失败优化），但**仅在无 `Content-Encoding` 时可用**——有编码时该头是压缩长度，压得好的图可能「压缩后 > 上限、解压后 < 上限」被误杀；早失败与流式超限都要 cancel body 释放连接。最终仍以流式计数为准——gzip/chunked 下该头不可信。`opts.maxBytes` 仅测试注入。流式读取最后要合并成单个 `Uint8Array`，峰值约为 **2× 上限/项**（分块 + 合并）再叠 `Blob` 复制；上限把 3 并发峰值封顶在数百 MiB 量级，避免 OOM 杀死扩展宿主、整批任务无法进入 4.4 报告；升级时机：真实渠道需要更大文件时调高常量或改流式上传（§6）。

下载与上传串行，单个转存项最坏 60s + 60s；进度仍按 item 完成计数（T6 口径），不加心跳。60s 与 50 MiB 联合等价于要求约 **≥7 Mbps** 持续下行（50 MiB ÷ 60s）——慢网下接近上限的图会被判超时，这是与 4.2 同口径的有意取舍；若真实使用中慢网失败集中，单独放宽下载超时即可（4.2 的 60s 只约束上传）。

### 2.3 非图片校验：字节嗅探为准

FR-5 明确「非图片内容」计入失败。三种判据：

- ❌ Content-Type 头——图床/CDN 常对合法图给 `application/octet-stream`（误杀），HTML 错误页也可能配 `image/*`（漏放）
- ❌ URL 扩展名——转存 URL 常无扩展名或带签名查询串，不可信
- ✅ 字节签名——与内容权威一致，且顺带给出正确扩展名（§2.4 上传 MIME 依赖它）

签名表（只看前 512 字节，不解析、不解码，字节原样上传）：

| 格式 | 判据 |
| --- | --- |
| png | `89 50 4E 47 0D 0A 1A 0A` |
| jpeg | `FF D8 FF` |
| gif | `GIF87a` / `GIF89a` |
| webp | `RIFF` … offset 8 起 `WEBP` |
| avif | offset 4 起 `ftyp`，前 32 字节含 `avif` / `avis` |
| bmp | `BM` |
| ico | `00 00 01 00` |
| svg | 去 BOM/前导空白后，跳过可选的 XML 声明、注释、非 HTML 的 DOCTYPE（`<!DOCTYPE svg ...>`）；512 字节窗口内、首个 `<svg` 之前若出现 `<html` 或 `<!doctype html>` 判非图；否则出现 `<svg`（大小写不敏感）即 SVG |

判不出 → 抛「非图片内容（Content-Type: <值>）」，T6 已把异常变成失败项、回写集不含该 key（原链接保留）。格式集合与 4.1 的九种扩展名对齐（8 种签名，`jpg`/`jpeg` 合流），但不是复用 parse 的扩展名粗筛（方向相反：那边「扩展名 → 是否解析」，这边「字节 → 格式」）。与 4.9 的「本地不维护格式限制清单」不冲突：这里只判定「字节是不是图片」，防把 HTML 错误页当图上传；判出的格式照样交服务端权威裁决。

SVG 的 prolog 必须容忍：典型文件可能以 `<?xml ...?>`、`<!DOCTYPE svg ...>` 或注释开头；只查「文件开头是不是 `<svg`」会误杀合法 SVG。HTML 判定按窗口内**先后顺序**（`<html`/`<!doctype html>` 出现在 `<svg` 之前即非图），不只看到「起头」——`<?xml?><html>…<svg>` 这类错误页也排除。UTF-16 BOM 不支持（按非图片失败，§6）；BMP/ICO 的 2/4 字节签名偏弱，可能误放文本，最终由服务端裁决（4.9）。

### 2.4 转存文件名：URL basename + 嗅探扩展名对齐

纯函数 `transferFileName(url, ext)`，`ext` 为嗅探结果：

1. 取文档中原 URL（非重定向后的最终 URL，后者常是签名/无意义路径）的 pathname 最后一段；`decodeURIComponent` 失败保留原值（4.1 同容错）；空段或 URL 无法解析回退 `remote`
2. Windows 文件名非法字符（`< > : " / \ | ? *`）与控制字符替换为 `_`；去首尾空白、去尾部连续的点；清空后回退 `remote`
3. 拆出最后一个点后的原扩展名（大小写不敏感）：与嗅探结果等价（`jpg` 接受 `jpg`/`jpeg`，其余同名）→ **保留原扩展名原样（含大小写）**；否则替换为嗅探的规范化扩展名；无扩展名则追加
4. 产物 = `<name>.<扩展名>`；`jpeg` 统一为 `jpg` 只发生在替换/追加，不发生在「原名匹配」分支

理由：`client.ts` 的 multipart Content-Type 由文件名扩展名推导（`mimeOf`）——`a.png` 实际是 JPEG 时必须改成 `.jpg`，否则上传 MIME 错标；同时文件名是服务端 `uploadNameType` 的命名素材。不加时间戳/序号：落库名由服务端命名策略裁决，本地去重只在落盘场景有意义（T9）。同名不同图的覆盖风险见 §6，T11 在真实图床验证。

**长度与兜底**：base 截断到 100 个 code point（`[...base]` 计数，避免拆开代理对），截断后重新去尾部空白/点；base 为空或全为点 → `remote`。`transferFileName` 不抛错：非法 URL 按空 basename 处理。

**兜底名的确定性撞名**：`remote.<ext>` 在 `uploadNameType: origin` 下必然同名——两张无可用 basename 的远程图（如 `...?id=1`、`...?id=2`）都叫 `remote.png`。T11 同名覆盖验证必须覆盖该形态（以及本地图与远程图同名）；若真实图床确认覆盖，优先给兜底名（必要时所有转存名）追加 4–6 位 URL 哈希。

- ❌ 被否：`Content-Disposition` 文件名——RFC 5987 / `filename*` 解析成本大于收益，URL basename 已覆盖常见形态，缺名有 `remote.<ext>` 兜底
- ❌ 被否：URL 原名原样透传、不改扩展名——同「a.png 实为 JPEG」，MIME 错标
- ❌ 被否：URL 带查询串整段当名——`?` 非法且含签名参数，已由 pathname 切分规避

### 2.5 网络与安全边界

- 仅 `http`/`https`：parse 只产出这两类，`downloadRemote` 再用 `new URL` 做一次防御校验，非法 →「远程图像地址无效」
- **绝不携带图床凭据/自定义头**：只带显式 `User-Agent: ImgBed-Uploader` 与默认 `Accept`，fetch 显式 `credentials: 'omit'`，不带 `Authorization`/`Cookie`/`Referer`。第三方站点的 401/403 不是图床认证问题。错误用普通 `Error` 而非 `UploadError`——flow 的 `authError`（「重新设置认证信息」按钮）只在 `UploadError` 401/403 时置位，下载侧不会误弹
- **显式 UA 但不伪装浏览器**：Node 内置 fetch 默认 UA 是 `node`，不少 CDN/防盗链会直接 403；设置 `ImgBed-Uploader` 只做诚实标识，不承诺绕过防盗链。无 Referer、无 cookie：防盗链站点 403 按 FR-5 计入失败报告（原链接保留）
- 非 2xx 与 `Content-Length` 早失败都不读 body，调用 `res.body?.cancel()` 释放 keep-alive 连接（cancel 自身异常吞掉）；不解析错误字段（4.9 是上传侧口径），HTTP 状态码足够定位
- 重定向交给 fetch 默认行为（follow，上限 20 跳）；最终 host 不再复判白名单/自识别——策略在下载前已定；重定向落到图床域只是一次多余搬运，回写后新 key 下次执行命中自识别（T6 §2.2）。重定向也不拦截私网/loopback（本机/内网图片是合法用例），风险与升级时机见 §6

### 2.6 失败语义：复用 T6 报告，不改 flow

| 原因 | 报告文案（`ItemResult.error`） |
| --- | --- |
| URL 非法 / 非 http(s) | `远程图像地址无效` |
| 网络异常（DNS/连接重置） | `下载失败：<cause>`（与 T2 同法取 `err.cause.message` 兜底，避免只剩 `fetch failed`） |
| body 读取被非超时中断（服务端半途断连） | `下载失败：<cause.message ?? message>`（如 `other side closed`；不让 `terminated` 裸奔） |
| 超时（建连/响应头/响应体） | `下载超时（60 秒）`（`opts.timeoutMs` 仅测试，文案固定 60 秒） |
| 超出大小上限 | `远程图像过大（超过 50 MB）`（`opts.maxBytes` 仅测试，断言前缀） |
| 非 2xx | `下载失败：HTTP 403` |
| 非图片字节 | `非图片内容（Content-Type: text/html）`（头值截断 100 字符，缺失显示 `（无）`） |

T6 `runUploads` 已把这些 message 变成失败项、进摘要与 Output Channel，「重试失败项」重跑会重新下载。T10 零改动这条链路。远程 401/403 是普通 `Error`，不会触发 `authError`。

## 5. 测试方式

`download.test.ts` 普通 mocha，两层：

**纯函数矩阵**

- `sniffImageExt`：8 种签名（9 个扩展名，`jpg`/`jpeg` 合流）正例；SVG 带 BOM / XML 声明 / `<!DOCTYPE svg ...>` / 注释 / `<SVG>` / 前导空白的变体；HTML（`<!doctype html>` 起头、`<html>` 起头、以及 `<?xml?><html>…<svg>` 先 HTML 后 `<svg>`）、空字节、纯文本、截断头（只有 `FF D8`）、12 字节 WebP 边界、`RIFF` 但非 `WEBP`、`ftyp` + `heic`、不足 4 字节的 ICO 负例。
- `transferFileName`：`https://x/a/b.png` → `b.png`；`%E5%9B%BE%201.PNG` → `图 1.PNG`（扩展名匹配大小写不敏感）；`photo.jpeg` + `jpg` → `photo.jpeg`（不换名）；`photo.php` + `jpg` → `photo.jpg`；无扩展名 → 追加；`?x=1` 不参与；`.../%zz.png` 解码失败保留原值；非法字符 `%3C%3E%3A` → `_`；尾部点/空白清理；空段 → `remote.png`；只有扩展名 `.png` → `remote.png`；非法 URL → `remote.png`；300 字符名截断到 100 code point 且保留扩展名。

**网络（`node:http` 进程内 server，与 `client.test.ts` 同法）**

- 200 + `image/png` + PNG 字节 → `name` 来自 URL、`data` 字节逐字一致。
- 200 + `application/octet-stream` + PNG 字节 → 成功（证明判定不看 Content-Type）。
- **200 + `image/png` + JPEG 字节 → `name` 以 `.jpg` 结尾**（证明「嗅探 → 改名 → MIME」整条链路，不只测纯函数）。
- **200 + `image/png` + HTML 字节 → 「非图片内容」**（证明头撒谎时不漏放）。
- 200 + `text/html` + HTML 字节 → 「非图片内容」。
- 200 无 `Content-Type` + PNG 字节 → 成功；200 + 空 body → 「非图片内容」。
- 403 / 404 → 「下载失败：HTTP <status>」；断言非 2xx 的响应体被 cancel（可选）。
- 连接拒绝（关闭端口）→ 「下载失败」。
- 服务端不响应 + `timeoutMs: 50` → 「下载超时」。
- **服务端返回响应头 + 部分 body 后卡住 + `timeoutMs: 50` → 「下载超时」**（证明捕获范围含 body 读取）。
- **服务端发部分 body 后 `destroy()` socket → 「下载失败：…」**（断言不是英文 `terminated` 裸文案，§2.6）。
- **`maxBytes: 100` + 超过 100 字节的图片 → 「远程图像过大」**（无 Content-Length、chunked 传输，证明流式计数不依赖该头）。
- 302 → 图片：跟随重定向成功。
- `file:///x.png` → 「远程图像地址无效」。
- **远端没收凭据**：mock server 断言 `authorization`/`cookie`/`referer` 为空，`user-agent === 'ImgBed-Uploader'`。

**集成（T11，mock 图床 + mock 远程图）**：验收 1 端到端（3 本地 + 白名单远程不动 + 非白名单远程下载/上传/回写共 4 条链接，白名单链接保持原样）；第二次执行全部跳过（验收 4）；远程 403 → 失败项、原链接保留（验收 2 机制），且不出现「重新设置认证信息」按钮。

**T11 手工验证（真实图床）**：`uploadNameType: origin` 下三种同名形态是否覆盖——①两个不同远程图都叫 `image.png`；②两个无可用 basename 的远程图（`...?id=1`/`id=2`，都落 `remote.png`，确定性撞名，§2.4）；③本地图与远程图同名。若覆盖，优先给兜底名（必要时所有转存名）追加 4–6 位 URL 哈希后再冻结。真实防盗链站点对 `ImgBed-Uploader` UA 的 403 行为一并记录。

## 6. 边界说明

- **防盗链 / 需登录的远程图**：403 进失败报告（FR-5 明确「403 计入失败」），不做 Referer 伪造/浏览器 UA 伪装或凭据转发；`ImgBed-Uploader` 只是诚实标识。
- **大小上限 50 MiB（解压后）**：`res.body` 流式累计，超限 cancel 并失败；`Content-Length` 仅在无 `Content-Encoding` 时作早失败提示（否则是压缩长度，会误杀），gzip/chunked 下以实际计数为准。流式分块最终要合并成单个 `Uint8Array`，单 item 峰值约 2× 上限，叠 3 并发 + `Blob` 复制后仍有界；升级时机：真实渠道需要更大文件时调高常量或改流式上传。
- **私网/loopback 不拦截**：本机/内网图片是合法需求，且测试用 `127.0.0.1`。已知风险：转存默认关闭时风险低；开启后不可信文档可能借转存 GET 内网图片（如摄像头快照）并上传到公开图床、回写链接。升级时机：收到相关报告时，在上传前检查 `res.url` 的最终 host，拒绝 loopback/private/link-local（测试需 opt-out）；GET 本身不拦截。
- **同名文件覆盖风险**：转存名不含时间戳/哈希；`uploadNameType: origin` 下不同远程图同名可能覆盖（T11 真实图床验证）。**兜底名 `remote.<ext>` 是确定性撞名**（所有无 basename 的远程图同名），验证必须覆盖该形态；若确认覆盖，优先给兜底名（必要时所有转存名）追加 4–6 位 URL 哈希（保留可读名）。
- **UA 不是反防盗链手段**：显式 `ImgBed-Uploader` 只做诚实标识，部分站点仍 403，按 FR-5 计入失败。
- **4.1 清单外格式**（tiff/heic 等）→ 按「非图片」失败（与 4.1 粗筛同口径；升级时机：需求扩格式清单）。
- **`Content-Disposition` 忽略**：URL 无可用名时统一 `remote.<ext>`，服务端改名兜底。
- **重定向后的最终 URL 不入 key**：key 仍是文档里的原 URL；回写后变图床 URL，下次执行命中自识别。重定向到图床域会多搬一次，接受。
- **同一 URL 在一次执行内只下载一次**（T6 按 key 去重）；失败重试会重新下载（无缓存）。
- **下载超时是总时限（含响应体读取）**，与上传超时各自独立：单个转存项最坏 60s + 60s。60s 与 50 MiB 上限联合要求约 ≥7 Mbps 持续带宽，慢网下接近上限的图会被判超时（有意取舍，4.2 的 60s 只约束上传；需要时单独放宽下载超时）。
- **取消不打断 in-flight 下载**（与 T6 §2.4 同款）：取消只停派发新项，正在下载/上传的项照常完成并按 4.4 回写；最长等到该项完成或超时（60s + 60s）。
- **并发**：转存项与本地项共享 `runUploads` 的 3 个 worker，下载与上传在同一 worker 内串行，不额外占并发。
- **SVG 判据容忍 prolog、只认文本前缀**：XML 声明 / 注释 / 非 HTML DOCTYPE 后允许 `<svg`；`<html` / `<!doctype html>` 只要在 512 字节窗口内先于 `<svg` 出现即判非图（不只「起头」）；UTF-16 BOM 不支持，prolog 超过 512 字节按非图片失败。其余 polyglot 理论可误判为图——上传后由图床/服务端裁决（4.9），本地不做内容安全审查。
- **BMP/ICO 签名偏弱**：`BM` / `00 00 01 00` 可能误放文本，最终由服务端裁决（4.9）；升级时机：出现误放报告再加强头部字段校验。
- **远程 URL 与文档目录无关**：untitled 文档照常转存（4.8 只约束本地路径）。
