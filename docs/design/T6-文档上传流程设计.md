## 1. 范围

`flow.ts`：文档上传流程编排——解析（T4）→ 选区/远程过滤与去重分组（纯）→ 路径解析与读文件（4.8）→ 并发 3 上传（T2；FR-5 转存经 `download` 接口注入）→ 回写（T5，4.7 单次 `WorkspaceEdit`）→ 报告（4.4）与进度/取消/互斥（4.5）。**不做**：FR-4 文件上传（T7）、`download.ts` 实现（T10，本任务只定注入接口）、粘贴（T9）、customCdn 逻辑（4.3 已在 client，T8 补验收场景）。

## 2. 方案与取舍

### 2.1 分层：一文件两层，纯核心零 vscode 依赖

`flow.ts` 内分两层：**纯核心**（`planUploads` / `runUploads` / `resolveLocalPath`，文件读取、下载、上传、进度、取消全部走注入接口）+ **vscode 壳**（`uploadDocument`：buffer 取文本、offset→Position、`WorkspaceEdit`、`withProgress` 接线、报告调用）。纯核心不 import vscode，`flow.test.ts` 以 fake IO 直测「去重、幂等、部分失败」（PLAN §4 单测口径）；壳层归 T11 集成测试。offset→Position 转换在壳内（PLAN §1「转换放在 flow/ui 层」）。

- ❌ 被否：纯决策拆独立 `plan.ts`——PLAN 模块清单没有它，一文件两层已满足可测性
- ❌ 被否：编排塞进 `commands.ts`——命令注册表保持装配薄壳（T1 模块划分）

### 2.2 去重与幂等：按 key 分组，remote 默认跳过

`planUploads` 把 refs 按 `key` 分组为 `UploadItem`（一组 = 一个文件 = 一次上传），组内全部引用共享回写 URL（验收 10：3 处引用只传 1 次、3 处回写同一链接——T5 的 `urlByKey` 天然支持多区间同 URL）。回写范围不止组内：**成功 key 的全部引用都回写**（含选区外、上传期间新出现的同 key 引用——4.6「多处回写同一链接」公共规则，§2.3 重定位即此口径，FR-2 细节见 §2.6）。远程策略（FR-1/5）：`target.type === 'remote'` **默认跳过**（回写后全是 remote，二次执行零上传、零改写）；`uploadRemoteImages` 开启时按序判定：**已回写自识别**——`host ∈ {serverUrl host、customCdn host}` 跳过（4.6 首句「重复执行不重复上传已回写的远程链接」明文优先于 FR-5 字面：转存刚回写的链接永不收敛、验收 4 直接失败；语义自洽——已在目标图床上的图再搬就是重复文件）→ 命中白名单（5.4）跳过 → 其余进计划转存（`source: remote`）。自识别与白名单同按 **hostname** 比较（customCdn 取其 URL 的 host，无 scheme 前缀补 `https://` 再解析）。如此 4.6 幂等与验收 4/12 在转存开/关两种配置下均成立。

白名单匹配口径：`target.host`（T4 已取 `URL.hostname`，大小写已归一）与白名单条目 **trim + 小写后等值**比较——5.4「精确匹配」指不支持通配与子域（`a.example.com` 不匹配 `example.com`），不是大小写敏感（用户写 `img.Shields.IO` 不应永不命中）。

- ❌ 被否：严格按 FR-5 字面「非白名单一律转存」——转存开启时每次执行都把刚回写的图再下载重传，图床永不收敛，违背 4.6 首句与验收 4；自识别缺口（`publicUrl` 异域前缀、旧 `customCdn`）记 §6，以白名单规避

### 2.3 回写竞态：回写前重解析重定位，单次 WorkspaceEdit

上传耗时以秒计，期间用户可能编辑文档——基于起始快照的偏移会错位 = 误改文本（解析器红线）。方案：回写前用**当前 buffer 重新 `parseImageRefs`，按本次成功 key 集合过滤，重新 `buildReplacements`**，一次 `WorkspaceEdit` 提交。key 仍命中说明引用还在（挪了位置，区间也是新的）；用户改掉引用（key 变化）→ 不命中 → 不动（尊重手改）。`urlByKey` 与文档解耦、T5 接口文本无关，重定位零成本。

重解析→构造 `WorkspaceEdit`→调用 `applyEdit` 必须是**同步原子段，不得夹 `await`**（extension host 单线程，期间 buffer 不可能再变，§2.3 竞态才算真正堵死）；实现上确需 await 时，以 `document.version` 变化触发**重解析重试**（这是重定位循环，不是被否掉的「中止」），重试限 3 次、超限放弃回写并提示（防用户持续编辑下空转；正常路径是同步原子段，不会触发重试）。

单次 `WorkspaceEdit` = 验收 3「一次 Ctrl+Z 完整撤销」。与 4.4「成功的项立即回写」的调和：**语义上**成功项必回写（不因后续失败/取消回滚），**执行上**批次末一次提交（失败语义见 §2.5）。

- ❌ 被否：`document.version` 校验、变了就中止回写——用户白上传，违背 4.4
- ❌ 被否：逐项 `applyEdit`——多次 Ctrl+Z 才能撤销全批，违背 4.7/验收 3

### 2.4 并发 3 与取消：worker 池，取消只停派发

3 个 worker 消费任务队列（4.2 固定并发，按文档顺序派发），`onProgress(done, total)` 接 `withProgress`（4.5「第 x/y 张」）。取消（4.5）：**停止派发新任务，in-flight 不 abort**，完成后照常回写——已传成功的文件已在图床上（4.4）；单请求 60s 超时封顶（T2）。取消未开始的项计入报告「跳过」。

- ❌ 被否：取消即 `AbortSignal` 中止 in-flight——服务端可能已存文件而本地没拿到 URL，再传一次就是重复文件

### 2.5 失败语义与重试（4.4）

结果按 key 聚合 `ItemResult`（一项 = 一个文件，去重后的语义）：成功项带 `url`（4.3 优先级已由 client 解析好），失败项带 `error`（`UploadError.message` 透传 4.9；本地读失败「文件不存在或不可读」；untitled 相对路径「未保存文档无法解析相对路径，请先保存」）。报告：通知摘要（成功 n / 失败 m / 跳过 k）+ 失败时「重试失败项」按钮，失败含认证类错误（401/403）时附「重新设置认证信息」按钮（复用 T3 按钮体系，4.9 可行动作）；逐项明细（含跳过原因）进 Output Channel（ImgBed Uploader）。摘要计数按**上传项（key）**，明细注明回写处数（同 key 3 处 → 成功 1 项、明细「回写 3 处」）——避免 n 被读成引用处数。

「重试失败项」= 以失败 key 集合为 `onlyKeys` 重跑编排入口：重新 parse 当前 buffer、只计划这些 key（§2.3 重定位天然兼容文档变化；key 已消失就少试几项，报告注明实试数）。按钮**仅当失败含可重试 key 时显示**——纯可疑跳过失败（无 key）不显示，点它只会「实试 0 项」。

- ❌ 被否：注册 `retryFailed` 命令——通知按钮闭包直接复用编排入口，T1 命令清单不动
- 跳过项（远程默认跳过 / 白名单 / 取消未开始）计入摘要「跳过 k」——验收 4「第二次全部跳过」需要可见反馈（4.4 呈现形态的增强，明细口径不变）；选区外引用**不计**跳过（FR-2 语义上不在范围内）
- `parseImageRefs` 的可疑跳过（`ParseResult.skipped`，T4 保守策略）按 PLAN 风险表口径**列入失败报告**：逐项（区间 + 原因）进 Output Channel、计入摘要失败 m；同样**按选区过滤**（FR-2 只报选区内，uploadAll 全量报，与「选区外不计」同口径）；无 key 不进「重试失败项」的 `onlyKeys`，修正语法后重新执行命令即可

### 2.6 FR-2 选区过滤：区间相交即命中

选区与引用的判定区间**相交**即命中：inline/html 按 `[urlStart, urlEnd)`，refdef 按任一 `useSpans` **或**定义行 URL 区间 `[urlStart, urlEnd)`（T4 §2.4 口径——选中第 2 个及以后的 `![a][r]` 不漏判，选中 `[r]: ./x.png` 定义行同样命中）。选区过滤只决定**上传范围**（哪些 key 进计划）；回写范围按 §2.2/§2.3 = 成功 key 的全部引用——FR-2「原位回写」指原位替换 URL，不是只换选中那一处，4.6 公共规则优先（选中 1/3 处同 key 引用 → 上传 1 次、3 处全回写，记 §6）。选区不含任何引用 → 提示并退出，不改文档（FR-2）。选中远程引用的行为与 FR-1 远程策略一致（需求未单独定义 FR-2 的远程语义，取统一策略，记 §6）。

### 2.7 路径解析（4.8）

local 的 `target.path` 相对**文档所在目录**解析（绝对路径含 Windows 盘符 / UNC 直接使用）；untitled 无目录 → 相对路径项失败「先保存文档」，绝对路径项照传（验收 13）。文件读取走 `vscode.workspace.fs.readFile`（远程工作区 / WSL 兼容），失败 → 失败项；上传文件名 = basename。字符串路径 → `vscode.Uri` 由壳层完成：以 `document.uri` 为 base 派生（`uri.with({ path })` 保留 scheme/authority，Windows 盘符/反斜杠先归一为 URI path 形态），untitled 无 base 时绝对路径退 `Uri.file`；工作区内路径**不用裸 `Uri.file`**（丢 scheme 即毁掉远程兼容）。FR-5 转存经注入接口 `downloadRemote(url) → { name, data }`（T10 实现下载、超时、非图片校验与转存文件名规则）。

## 3. 接口

```ts
// flow.ts：纯核心（planUploads / runUploads / resolveLocalPath）不 import vscode；
// 壳（uploadDocument）import vscode。
export type UploadItem = {
  key: string;
  refs: ImageRef[]; // 同 key 全部引用（去重组）
  source:
    | { type: 'local'; path: string } // 文档形态路径，读取前经 4.8 解析
    | { type: 'remote'; url: string }; // FR-5 转存
};

// 可辨识联合（对齐 T3 TestResult 风格）
export type ItemResult =
  | { key: string; ok: true; url: string } // 成功：回写 URL
  | { key: string; ok: false; error: string }; // 失败：逐项原因（4.4/4.9）

export type PlanResult = {
  items: UploadItem[]; // 文档顺序派发
  skipped: { key: string; reason: string }[]; // 跳过明细进 Output Channel
};

// 纯：onlyKeys 过滤（重试）→ 选区过滤（FR-2）→ 远程策略（自识别 → 白名单 → 转存，FR-5/4.6）→ 去重分组（4.6）
export function planUploads(
  refs: ImageRef[],
  opts: {
    selection?: { start: number; end: number };
    uploadRemoteImages: boolean;
    remoteWhitelist: string[];
    selfHosts: string[]; // 已回写自识别：serverUrl/customCdn 的 hostname（§2.2）
    onlyKeys?: Set<string>; // 「重试失败项」：只计划这些 key（不入计划的不计跳过）
  },
): PlanResult;

// 纯：4.8 路径解析。docDir 为 undefined（untitled）时相对路径无法解析
export function resolveLocalPath(
  docDir: string | undefined,
  p: string,
): { ok: true; path: string } | { ok: false; error: string };

// 纯：并发 3、进度/取消钩子、结果聚合。
// io.readLocal 收文档形态路径（壳层闭包内 resolveLocalPath + fs，失败 throw Error(原因)）。
// 返回仅含已尝试项；未派发数 = items.length - results.length（取消未开始）。
export async function runUploads(
  items: UploadItem[],
  io: {
    readLocal(path: string): Promise<Uint8Array>;
    downloadRemote(url: string): Promise<{ name: string; data: Uint8Array }>;
    upload(file: { name: string; data: Uint8Array }): Promise<{ url: string }>;
  },
  hooks: {
    onProgress(done: number, total: number): void;
    isCancelled(): boolean;
  },
): Promise<ItemResult[]>;

// vscode 壳：ensureReady（4.10 引导前置，拿不到 Config 直接返回）→
// parse 当前 buffer → planUploads → runUploads →
// 重解析重定位（§2.3 同步原子段）→ 单次 WorkspaceEdit → 报告（ui.ts）。
// io.downloadRemote T6 期注入抛错桩（转存默认关闭，不可达），T10 以 download.ts 实现替换（接口不动）。
export async function uploadDocument(
  editor: vscode.TextEditor,
  opts: {
    selection?: { start: number; end: number };
    onlyKeys?: Set<string>; // 「重试失败项」只跑失败 key
  },
): Promise<void>;
```

较 PLAN §2 草案的偏差（登记 PLAN「变更记录」）：`ItemOutcome`（per-ref）改 `ItemResult`（per-key 可辨识联合，落实去重分组语义）；`uploadDocument` 明确收 `TextEditor` + 选项（`selection`/`onlyKeys`），返回值改 `Promise<void>`（草案 `Promise<ItemOutcome[]>`——结果经报告呈现、重试经 `onlyKeys` 复用入口）；`planUploads` 补 `selfHosts` 选项（§2.2 自识别）；白名单 hostname 匹配随 `planUploads` 落 T6（编排必需），T10 职责收窄为 `download.ts` 实现。

## 5. 测试方式

`flow.test.ts` 普通 mocha 纯单测：fake `io`（记录调用与并发峰值）+ fake `hooks`。核心用例：

- **去重分组**（验收 10 上传侧）：同 key 3 引用 → 1 item、`upload` 只调 1 次、`refs` 含 3 区间。
- **幂等与远程策略**（验收 4/12）：remote 默认跳过；转存开启 + 白名单命中 → 跳过；转存开启 + 非白名单 → `downloadRemote`→`upload` 链路（fake 断言传参）。
- **转存幂等自识别（§2.2）**：remote host = serverUrl host 或 customCdn host → 跳过不转存（转存开启亦然）；异域 host → 转存。
- **转存下载失败**（FR-5）：`downloadRemote` 抛错 → 失败项、error 透传、回写集不含该 key（原链接保留）。
- **白名单匹配**（5.4）：精确等值、条目大小写/空白容错、子域不命中。
- **选区过滤**（FR-2）：命中 inline 区间 / refdef 第 2 个 `useSpan` / refdef 定义行 URL 区间 / 跨行多引用 / 选区无引用 → 空计划。
- **路径解析**（4.8 / 验收 13）：`resolveLocalPath` 相对拼文档目录、绝对/盘符/UNC 直用、untitled 相对 → 错误文案「先保存」；`readLocal` 抛错 → 失败项。
- **部分失败**（验收 2）：3 项 1 失败 → 聚合正确、error 透传、成功项保留。
- **并发 3**（4.2）：fake upload 慢响应，断言并发峰值 ≤ 3 且全部完成。
- **取消**（4.5）：`isCancelled` 翻真后不再派发；已成功项保留在结果，未派发数 = items − results。
- **重试过滤**：`onlyKeys` 只计划失败 key。
- **重定位过滤**（§2.3 纯部分）：成功 key 过滤后 refs 与新文本区间对齐，含选区外同 key 引用（§2.6 口径）；key 已被用户改掉 → 不回写。

集成测试（T11，`@vscode/test-electron` + mock 图床）：验收 1–5、10、12、13 端到端 + undo 断言（验收 3）。

## 6. 边界说明

- 上传中用户编辑文档：回写重定位（§2.3）；用户手动改掉的引用（key 变化）不回写。
- 取消不 abort in-flight（§2.4）；单请求 60s 超时封顶（T2）。
- FR-2 选中远程引用与 FR-1 同策略（需求未定义，取一致）。
- FR-2 回写范围：同 key 选中 1/3 处 → 上传 1 次、3 处全回写（4.6 公共规则优先于「原位」字面），上传期间新增的同 key 引用同样回写（§2.2/§2.3）。
- 自识别缺口（§2.2）：`publicUrl` 为异域前缀（服务端「默认 URL 前缀」配了别的域）或旧 `customCdn`（改过配置）识别不到，转存开启时会被再搬运——加 `remoteWhitelist` 规避。
- 重解析→applyEdit 为同步原子段，不得夹 `await`（§2.3）；确需 await 时 `document.version` 变化触发重解析重试。
- 解析可疑跳过计入失败报告与失败 m（PLAN 风险表口径），不进「重试失败项」——修正语法后重新执行命令。
- 计划为空分三种：refs 与可疑跳过皆空 → 提示「未找到图像引用」退出不改文档；有可疑跳过 → 走失败报告（§2.5）；有引用但全被策略跳过 → 正常报告（成功 0 / 跳过 k）。
- 重试时文档大改：消失的 key 不试，报告注明实试 n 项。
- 通知摘要「跳过 k」含取消未开始项与幂等/白名单跳过项；选区外引用不计跳过（§2.5）。
- `uploadDocument` 互斥锁全命令共享一把（4.5「不并发两批任务」），锁与报告住 `ui.ts`。
- 超大文档 parse 两次（执行前 + 回写前）：O(n) 扫描，可接受。
- 跳过与失败分开呈现：跳过是策略行为不是错误（4.4 报告只列失败原因，跳过进明细与摘要计数）。
