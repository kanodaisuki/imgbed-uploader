# T9 方案设计：粘贴上传

- 状态：已冻结（2026-11-19 评审通过；勘误见文末「变更记录」）
- 对应任务：[`../plans/PLAN.md`](../plans/PLAN.md) T9（1d）
- 前置：T0（粘贴技术路线选型结论，[`T0-粘贴可行性验证.md`](T0-粘贴可行性验证.md) §8 为本文强制输入）、T2（client）。验收映射：验收 7、11
- 基线：[`../requirements/Requirement.md`](../requirements/Requirement.md) FR-3、4.2（超时 60s）、4.3（URL 优先级，client 已实现）、4.9（错误透传）

## 1. 范围

`paste.ts`：粘贴接管 provider——收集剪贴板图片字节（内存，零临时文件）→ 上传（T2 `upload()`）→ 插入 `![](url)`；失败自实现降级"落盘 + 本地链接"。**不做**：粘贴选择 widget 消噪（§6 优化项）、`resolveDocumentPasteEdit` 两段式（§2.2 被否）、FR-4 文件上传（T7）、`download.ts`（T10）。FR-3 不设命令（需求第 6 节），不改 `package.json` 命令清单。

## 2. 方案与取舍

### 2.1 技术路线：`DocumentPasteEditProvider`（T0 选型已定）

`vscode.languages.registerDocumentPasteEditProvider(selector, provider, metadata)`，selector `[{language:'markdown'}, {language:'mdx'}]`。**始终注册**（T0 V5）：`pasteUpload=false` 或无图片时返回 `undefined` 走默认粘贴，无 re-register 问题。`pasteMimeTypes` 沿用 spike 验证过的宽列表并**字面钉死**（`spike/` 结论后删除，列表不随之丢失）：`['image/*', 'image/png', 'image/jpeg', 'image/gif', 'image/webp', 'text/uri-list', 'files', 'text/plain']`——T0 全部结论基于该列表实测；只声明 `image/*` 是否同样触发文件粘贴未单独验证，不值得再赌一次。文本粘贴 1ms 返回 undefined（V8），宽列表无代价。

- ❌ 被否：方案 B 覆盖内置命令 / 方案 C 重绑 Ctrl+V / 方案 D 命令式「粘贴并上传」——T0 §2 已否，A 全验证点通过

### 2.2 单段式：上传在 `provideDocumentPasteEdits` 内完成

上传 → 成功返回 `DocumentPasteEdit`（`insertText = ![](url)`，title「上传到图床」），失败走 §2.3 降级。等待期间 VS Code 原生光标 loading + Esc 可取消（T0 V3），无需自研反馈。

- ❌ 被否：`resolveDocumentPasteEdit` 两段式（先返回占位 edit、再异步上传）——其失败回落行为未验证（T0 §5），只是省等待的优化；单段式管线已被 V3–V9 全量验证，不引入新风险面

### 2.3 失败降级自实现：落盘 + 本地链接（T0 强制输入 1）

上传失败 / 异常 / 超时 / 未配置凭据时，**插件自己**把图片字节写入**文档所在目录**（untitled → `workspaceFolders[0]` 根目录，多根取首个；无工作区见 §6），插入相对路径本地链接 `![](./name.png)`；untitled 无文档路径、相对链接解析基准不明（另存后失联）→ 插**绝对路径**链接（`localImageLink` 收可空 `docDir`，§3）。不依赖 VS Code 管线兜底：mdx 实测**零回落、图片静默消失**（T0 V4，6 次粘贴零插入零落盘），验收 11「截图不丢失」在 markdown 与 mdx 下都由本路径成立。

- 落盘位置取**文档所在目录**是对验收 11「保存到工作区」的**有意解释**：相对链接与 4.8「基于文档所在目录解析」同口径；失败路径必须自实现（mdx 零回落），接受绕过 `markdown.copyFiles.destination`
- **落盘自身失败**（只读远程 / 权限 / 磁盘满 / untitled 且无工作区）：提示「无法保存图片：\<原因\>」后该张不产出链接——字节无处安放，"绝不丢图"在此不成立，为唯一接受丢图的路径；全部图片都未产出链接 → 返回 undefined（流程 6，markdown 下内置兜底或可再救一次）
- 落盘用 `vscode.workspace.fs.writeFile`（远程工作区 / WSL 兼容，与 T6 读取口径一致）；文件名碰撞（同名已存在）追加 `-1`/`-2` 后缀
- 本地链接的 URL 上下文安全化**复用 `rewrite.ts` 的 `markdownText`**（空格/括号包 `<>`、定界敏感字符编码，T5 §2.3 口径），由内部函数改导出，不复制逻辑
- 降级前 fire-and-forget 弹 `showWarningMessage` 提示失败原因（FR-3；T0 V4 验证先弹提示不影响回落），不 await 用户操作、不阻塞粘贴返回
- ❌ 被否：返回 undefined 依赖内置 markdown 扩展落盘——mdx 丢图，违反"绝不丢图"

### 2.4 开关与未配置路径

- **`pasteUpload=false`**：返回 undefined 走**真** VS Code 默认行为（T0 V5 验证路线，FR-3 字面"关闭时走 VS Code 默认行为"）。mdx 下默认行为本身是丢图，作为已知边界记 §6（用户显式关闭接管，不替 VS Code 修补）。
  - ❌ 被否：关闭时也自实现落盘——不是"默认行为"字面语义（与 §2.3 失败降级的不对称是有意的：那边是"绝不丢图"强制、不得不绕过 `markdown.copyFiles.destination`，这边用户已显式关闭接管）
- **未配置 serverUrl / 凭据**：不走 `ui.ensureReady`（T1 既定：引导只在命令执行时触发；`ensureReady` 会 await 用户点按钮，粘贴路径不能被通知阻塞）。粘贴路径做**轻检查**（配置读取带 `document.uri` 作用域，`getConfig(resource)`，T1 多根/文件夹级覆盖口径；`serverUrl === ''` 或 `authType !== 'none' && !hasCredential()`），不满足 → 非阻塞提示（带「打开设置」/「设置认证信息」动作；**一次粘贴弹一条通知，多图不逐张弹**）→ 走 §2.3 降级（验收 11 明确以"未配置凭据"为失败示例）。

### 2.5 超时与取消（T0 强制输入 3）

- **超时**：复用 `client.upload()` 的 60s `AbortSignal.timeout`（4.2 固定值，`opts.timeoutMs` 已支持），超时抛 `UploadError` → 走 §2.3 降级。provider 挂起 = 粘贴永久挂起（T0 hang 实测），60s 封顶 + Esc 双保险。
- **取消**：`token.isCancellationRequested` 时**静默**返回 undefined——不弹错、不降级、不写盘（T0 V3：Esc = 放弃，无报错无残留）。guard 不止一处：**每张开始处理（含发起上传）前各查一次**（§3 流程 4，否则多图或临界 Esc 会继续上传、留下写盘与弹窗），返回 edit 前最终再查一次（流程 5）。
- ❌ 被否：取消即 abort in-flight 上传——`upload()` 无 signal 注入面，且 abort 后服务端仍可能已存文件（T6 §2.4 同款取舍）；取消后的迟到结果被 token guard 丢弃即可

### 2.6 异常自 catch + 自提示（T0 强制输入 2）

VS Code 静默吞掉 provider 异常（T0 V4 实测零报错），`provideDocumentPasteEdits` 全程 try/catch：`UploadError.message` 原样透传（4.9），非 UploadError 兜底 `String(err)`；提示后走 §2.3 降级。**任何路径都不返回"什么都不插"的失败**（除用户取消、关闭开关、落盘失败 §2.3、全部未产出链接时返回 undefined）。

### 2.7 图片收集、文件名与多图

- 取 `dataTransfer` 全部 `image/*` 文件项（`item.asFile().data()` 取内存字节；T0 V2 截图、V2b 复制文件均直接给完整字节，**不回读磁盘**）。非图片项忽略；一个图片项都没有 → 返回 undefined（V8）。
- **多张图全部处理**（如资源管理器多选复制）：逐张上传、逐张独立降级（一张失败不影响其余），每张一行 `![](url)`，光标落最后一条之后。被否：只处理首张——第二张起直接丢图，违反"绝不丢图"。
- 文件名：以 **`text/uri-list` 项是否存在**判别"复制的文件"与"截图"（spike 日志实测：截图的 DataTransferFile 带 VS Code 合成名 `image.png`，复制文件带真实名 + `text/uri-list` 源路径）——有源路径 → `file.name` 原样使用（T2 口径：文件名原样进 FormData，不转写）；无 → 生成 `paste-YYYYMMDD-HHmmss.png`（FR-3，**丢弃合成名 `image.png`**），扩展名按 mime 映射（`image/jpeg`→`jpg`、`image/svg+xml`→`svg` 等，默认 `png`）。同一次粘贴多张截图共享同一时间戳 → 生成名加序号（`paste-YYYYMMDD-HHmmss-2.png` 起），统一走 `resolveCollision` 去重（上传名、落盘名共用）。
- 等待/降级期间无并行粘贴互斥需求：V6 实测连续粘贴顺序稳定（插入位置严格递增）。

## 3. 接口与流程

```ts
// paste.ts：纯函数不 import vscode（paste.test.ts 直测）；vscode 壳负责注册与管线

// 文件名：sourceName（仅存在 text/uri-list 的"复制的文件"传 file.name，截图传 undefined）非空原样返回；
// undefined 则按 mime 生成 paste-YYYYMMDD-HHmmss.<ext>；撞名（同秒/同批）由 resolveCollision 统一去重
export function pasteFileName(now: Date, sourceName: string | undefined, mime: string): string;

// 远程链接：`![](${markdownText(url)})`（安全化复用 rewrite.ts，导出 markdownText）
export function mdImageLink(url: string): string;

// 本地链接：filePath 相对 docDir（含 ../、反斜杠转 /）；docDir 为 undefined（untitled）→ 输出绝对路径
export function localImageLink(docDir: string | undefined, filePath: string): string;

// 落盘改名：name 被占用时依次试 name-1、name-2…（exists 注入，纯函数）
export function resolveCollision(name: string, exists: (name: string) => boolean): string;

// vscode 壳：注册 provider（extension.ts 装配调用，与 registerCommands 同款）
export function registerPasteProvider(context: vscode.ExtensionContext): void;
```

provider 单次调用流程：

1. 收集图片项（§2.7）；无 → 返回 undefined。
2. `pasteUpload=false` → 返回 undefined（§2.4）。
3. 轻检查未配置 → 提示 + 每张走降级（§2.4/2.3；token guard 同步骤 4）。
4. 逐张（每张开始处理前先查 `token.isCancellationRequested`，命中则该张静默丢弃，§2.5）：`upload({ name, data }, cfg)` → 成功 `mdImageLink(url)`；失败/异常/超时 → `showWarningMessage` + 落盘 + `localImageLink`（§2.3/2.6）；落盘失败 → 「无法保存图片」提示后该张不产出链接（§2.3）。
5. await 全部结束后 `token.isCancellationRequested` → 返回 undefined（§2.5）。
6. 多张按序 `\n` 拼接；**拼接文本为空（全部未产出链接）→ 返回 undefined**（markdown 下内置兜底还有一次救图机会）；否则返回 `[new vscode.DocumentPasteEdit(text, '上传到图床')]`；插入/选区替换/光标位置/一次撤销均由 VS Code 管线保证（T0 V8/V9 已验证）。

URL 优先级（customCdn / publicUrl / serverUrl+src）已在 `client.upload()` 内解析（4.3），paste 不感知。

- **碰撞改名**：`base.png` 占用 → `base-1.png`；再占用 → `base-2.png`。

- **验收 7**：开启时粘贴截图 → 自动插入远程链接且光标在链接后；关闭时走 VS Code 默认行为。

## 6. 边界说明

- **`pasteUpload=false` + mdx**：返回 undefined 后无内置兜底，图片静默消失——这是 VS Code/MDX 扩展的默认行为本身（用户显式关闭接管，FR-3 字面语义）；markdown 下由内置扩展落盘正常。若后续不接受，再评估"关闭时也自实现落盘"（§2.4 被否项翻案）。
- **untitled 且无工作区**：无处落盘 = 落盘失败的一种原因（§2.3）：提示「无法保存图片：请先保存文档或打开工作区」，该张不产出链接，全部未产出 → 返回 undefined（markdown 下内置兜底或可救，mdx 下丢图，接受）。
- **Esc 取消**：不中断 in-flight 上传（60s 封顶）；取消后到货的结果/失败一律静默丢弃（token guard），服务端可能留孤儿文件（无管理 API，无法清理，无害）。
- **同一秒两次粘贴**：生成文件名相同——上传侧命名由服务端 `uploadNameType` 裁决（4.9 服务端权威）；本地落盘侧碰撞改名兜住（check-then-write 非原子，同秒并发降级仍有极小概率互相覆盖，接受为已知风险）。
- **多光标粘贴**：edit 对每个光标各插一条 → 上传一次、N 处同链接，与默认粘贴"每光标各插一份"一致。
- **混合内容**（如从 Word 复制图 + 文本）：只取 `image/*` 项，文本项忽略；一个图片项都没有才返回 undefined。
- **widget 噪音**（T0 V6b 已知问题，优化项）：内置 provider 同时返回 edit 必弹粘贴选择 widget，`yieldTo` 实测开/关无差异；默认项仍是我们的、零点击即时应用，非阻塞。消噪线索留待后续：内置 mime `application/vnd.vscode.markdown.updatelinks.metadata`、`DocumentDropOrPasteEditKind` 过滤、`markdown.editor.filePaste` 设置。
- **提示与降级的顺序**：先 fire-and-forget 弹提示、再返回降级 edit，互不阻塞（T0 V4 验证该顺序不影响回落）。
