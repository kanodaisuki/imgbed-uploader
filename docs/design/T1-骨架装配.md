# T1 方案设计：骨架装配

- 状态：草稿（待评审）
- 对应任务：[`../plans/PLAN.md`](../plans/PLAN.md) T1（0.5d）
- 前置：无。验收映射：验收 6（配置缺失引导部分）

## 1. 范围

装配插件骨架：`package.json` 的 `contributes.configuration`（13 项设置声明，含默认值、enum 与 `scope: resource`）、全部命令与菜单 `when` 子句、`config.ts`（设置读取规范化）、`secrets.ts`（凭据存取）、`commands.ts`（命令注册表）、`ui.ts` 的首次使用引导（需求 4.10）。本任务不做任何上传逻辑（T2 起）。

## 2. 方案与取舍

### 2.1 配置读取：每次现读，不缓存

`getConfig(resource?: vscode.Uri)` 每次调用直接读 `workspace.getConfiguration('imgbedUploader', resource)` 并做规范化。

- ✅ 零状态、零 `onDidChangeConfiguration` 记账，设置改动即刻生效
- ❌ 被否的备选：缓存 + 监听变更——设置读取每秒至多几次，缓存纯属负担

规范化规则（纯函数 `normalize(raw): Config`，与 vscode 绑定分离以便单测）：

| 字段 | 规则 |
| --- | --- |
| `serverUrl` | trim，去掉**全部**尾部 `/`（`https://x//` → `https://x`） |
| `customCdn` | trim，尾部统一为单个 `/`（拼接文件 ID 用），`''` 为未启用 |
| `channelName` / `uploadFolder` | trim |
| `remoteWhitelist` | trim + 转小写（匹配时按 hostname 精确比较，需求 5.4） |
| `authType` / `uploadChannel` / `uploadNameType` | 非法枚举值回退默认（`authCode` / `telegram` / `default`） |
| 其余（boolean / string） | 原样 |

`customCdn` 尾部补 `/` 的前提假设：文件 ID **不含前导 `/`**（4.3 的 `customCdn + 文件ID` 拼接口径由 T2/T8 落实时遵守此约定；若实测文件 ID 带前导 `/`，改拼接口径，不动本规范化）。

### 2.2 凭据：单字段 + SecretStorage

`secrets.ts` 封装 `context.secrets`，key 为 `imgbedUploader.credential`，提供 `set / get / clear / has`（`has` 即 `get() !== undefined` 的便捷封装）。凭据只存一份，`authType` 设置决定**怎么发**（query 或 Bearer 头，T2 实现）。

- ❌ 被否：按 authType 分两个 key——用户切换类型就得重录，单字段无歧义
- ❌ 被否：存 settings.json——凭据进仓库/设置同步，安全不可接受（需求 5 已定）

### 2.3 命令：T1 一次声明全部命令，未实现的挂桩

`package.json` 在 T1 就声明全部 5 个命令的标题、菜单和 `when` 子句（见 §4）；`commands.ts` 建注册表，`setCredentials` 与引导真实实现，其余命令先挂"功能开发中"桩。**桩命令同样先走 `ensureReady`，通过后才提示"功能开发中"**（保证 §6 手动测试可执行）。后续任务只填 handler，不再动 `package.json`。

- ✅ 菜单/键位/标题一次定型，早暴露 UX 问题；后续任务 diff 最小
- ❌ 被否：每个任务各自加命令——`package.json` 反复冲突修改，菜单布局要到最后才见全貌

### 2.4 首次引导：上传前置检查，按需弹

`ensureReady(resource?: vscode.Uri): Promise<Config | undefined>`（`ui.ts` 导出——PLAN §1 将首次引导 4.10 划归 `ui.ts`，`commands.ts` 的 handler 只负责调用；所有上传 handler 先调用，**传活动文档 URI**，多根工作区 / 文件夹级覆盖的 `serverUrl` 才能读对）：

1. `serverUrl` 为空 → 通知「未配置图床地址」，按钮「打开设置」→ `workbench.action.openSettings`（搜索 `imgbedUploader.serverUrl`）；返回 `undefined` 中止。
2. `authType != 'none'` 且无凭据 → 通知「未配置认证信息」，按钮「设置认证信息」→ 执行 `setCredentials`；返回 `undefined` 中止。
3. 通过则返回规范化后的 `Config`。

- ✅ 检查挂在命令执行时（每次上传前），配置好了就零打扰
- ❌ 被否：激活时检查弹窗——装完插件没用它就被弹，pushy；❌ 状态栏常驻指示器——额外 UI，v1 不需要

## 3. 模块与接口变更

对 `PLAN.md` §1 模块划分的落实，无结构变更（首次引导放 `ui.ts`，`commands.ts` 的 handler 只调用 `ensureReady`）。新增接口：

```ts
// config.ts
type Config = {
  serverUrl: string;                                   // 末尾无 /
  authType: 'authCode' | 'apiToken' | 'none';
  uploadChannel: 'telegram' | 'cfr2' | 's3' | 'discord' | 'huggingface' | 'webdav';
  channelName: string;
  uploadFolder: string;
  uploadNameType: 'default' | 'index' | 'origin' | 'short';
  expire: string;
  serverCompress: boolean;
  autoRetry: boolean;
  customCdn: string;                                   // 以 / 结尾，'' 为未启用
  uploadRemoteImages: boolean;
  remoteWhitelist: string[];                           // 小写 hostname
  pasteUpload: boolean;
};
function normalize(raw: Record<string, unknown>): Config;   // 纯函数，可单测
function getConfig(resource?: vscode.Uri): Config;

// secrets.ts
function setCredential(secret: string): Promise<void>;
function getCredential(): Promise<string | undefined>;
function hasCredential(): Promise<boolean>;
function clearCredential(): Promise<void>;

// ui.ts
function ensureReady(resource?: vscode.Uri): Promise<Config | undefined>;   // 引导 + 前置检查

// commands.ts
function registerCommands(context: ExtensionContext): void;
```

`setCredentials` 的输入用 `showInputBox({ password: true, ignoreFocusOut: true })`（简单可靠）；**输入为空或取消时不写入任何值**（不清动已存凭据）；❌ 被否：QuickInput 多步向导——只录一个值，向导是仪式感。

## 4. package.json 声明（本任务一次定型）

### 4.1 `contributes.configuration`

需求 §5 的 13 项设置（5.1×2 + 5.2×7 + 5.3×1 + 5.4×2 + 5.5×1）在本任务一次声明：类型、默认值、enum 候选、描述，除凭据外（凭据不进 settings.json）全部 `scope: resource`。不声明则 `getConfiguration().get()` 拿不到默认值、设置页搜不到，enum 也不受校验。

### 4.2 命令与菜单

| 命令 | 标题 | 菜单入口（`group`） | `when` |
| --- | --- | --- | --- |
| `imgbed-uploader.uploadAll` | 上传文档全部本地图像 | `editor/title`（`navigation`，icon `$(cloud-upload)`）、`editor/context`（`imgbed@1`） | `editorLangId == markdown \|\| editorLangId == mdx` |
| `imgbed-uploader.uploadSelected` | 上传选定图片 | `editor/context`（`imgbed@2`） | `editorHasSelection && (editorLangId == markdown \|\| editorLangId == mdx)` |
| `imgbed-uploader.uploadFile` | 上传本地图片 | `explorer/context`（`imgbed@1`） | `resourceExtname =~ /\.(png\|jpe?g\|gif\|webp\|avif\|svg\|bmp\|ico)$/i` |
| `imgbed-uploader.setCredentials` | 设置认证信息 | 命令面板 | （默认） |
| `imgbed-uploader.testConnection` | 测试连接 | 命令面板 | （默认） |

- **文案决策**：FR-4 原文资源管理器入口为「上传到图床」，VS Code 同一命令在所有菜单只有一个标题，统一为「上传本地图片」；需求文档需相应变更（见 §5）。
- `editor/title` 按钮必须配 `icon` 且 `group: navigation`，否则掉进 "..." 溢出菜单，违背 FR-1「最高频入口」的定位。
- 表中 `when` 为伪代码；package.json 实写注意 JSON 转义，如 `resourceExtname =~ /\\.(png|jpe?g|gif|webp|avif|svg|bmp|ico)$/i`。
- 粘贴上传（T9）不声明命令（事件驱动，需求第 6 节已定）。

## 5. 对既有模块的影响

无（绿地首个实现任务）。需求文档需一处文案变更（已按 `docs/README` 规则登记变更记录）：FR-4 资源管理器入口「上传到图床」→「上传本地图片」（决策见 §4）。本任务确立的约定供后续任务遵循：模块边界按 `PLAN.md` §1；`parse`/`rewrite` 不 import `vscode`；**`ui.ts` 不 import `commands.ts`**（引导中触发 `setCredentials` 用 `executeCommand('imgbed-uploader.setCredentials')` 字符串，避免与 `commands.ts` → `ui.ts` 的调用形成循环依赖）；提示文案简体中文（需求 2）。

## 6. 测试方式

- **单测**（普通 mocha，不启 VS Code）：`normalize()` 的规范化规则——`serverUrl` 尾斜杠（含多个尾斜杠）、`customCdn` 补 `/`、白名单小写、非法枚举值回退默认；并断言 `Config` 的 enum 候选与默认值同 `package.json` 的 `contributes.configuration` 一致（读文件对比，防两处声明漂移）。
- **手动**（F5 开发宿主）：
  - 清空设置执行任一上传命令（桩命令同样先过引导）→ 弹「未配置图床地址」+「打开设置」；配好地址清凭据 → 弹「未配置认证信息」+「设置认证信息」→ 输入后 `hasCredential()` 为真；重开窗口凭据仍在（SecretStorage 持久化）。
  - UI 定型检查：markdown/mdx 文档标题栏出现带图标上传按钮、其他语言不出现；编辑器右键、资源管理器右键菜单位置（`group`）正确。
- 无集成测试（T1 无网络、无文档编辑行为）。

## 7. 边界说明

- `expire` 不做本地格式校验（需求 4.9：服务端裁决，400 透传，T2 实现）。
- 引导只在命令执行时触发，`pasteUpload` 的粘贴路径不走 `ensureReady`（T9 处理：未配置时粘贴必须直接回落默认行为，绝不丢图）。
- 资源管理器多选/文件夹：`when` 的 `resourceExtname` 只约束右键目标，混选含非图片、或名为 `x.png` 的文件夹时菜单仍显示——handler 按扩展名常量过滤并排除目录；多选插入细则归 T7。
- 桩命令先走 `ensureReady`，通过后才提示「功能开发中」。
- `customCdn` 以 `/` 结尾隐含「文件 ID 无前导 `/`」假设（§2.1），T2/T8 拼接时遵守；若实测不符，改拼接口径不动规范化。
