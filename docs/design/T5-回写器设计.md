# T5 方案设计：回写器

- 状态：已冻结（2026-11-19 评审通过并实现，单测 21 项全部通过）
- 对应任务：[`../plans/PLAN.md`](../plans/PLAN.md) T5（0.5d）
- 前置：T4（`ImageRef` 区间产出）。验收映射：验收 3 的区间正确性部分（「一次 Ctrl+Z 完整撤销」由 T6 的单次 `WorkspaceEdit` 保证，本任务保证替换区间精确、应用顺序安全）
- 基线：[`../requirements/Requirement.md`](../requirements/Requirement.md) 4.7（只换 URL、倒序/整体提交、buffer 语义）、FR-6（回写 URL 来自 4.3 优先级解析结果）

## 1. 范围

`rewrite.ts`：`ImageRef[]` + `urlByKey: Map<key, url>` → `Replacement[]`（数字偏移），把每个引用的 **URL 区间**替换为新 URL。纯函数，不 import `vscode`（PLAN §1 依赖方向）。**不做**：去重与 URL 生成（4.3/4.6，T6 传入已解析好的 `urlByKey`）、选区过滤（FR-2，T6）、`WorkspaceEdit` 提交与撤销（4.7 执行层，T6）。

## 2. 方案与取舍

### 2.1 语义：区间替换，URL 之外零触碰

每个 `ImageRef` 的 `[urlStart, urlEnd)` 已精确覆盖 URL 原文（markdown 含 `<>` 包装、HTML 不含引号，T4 §2.7），替换只落在这段区间上——alt、title、引用式定义结构、引号、缩进、行内位置天然不动（4.7）。parse 保证区间互不重叠（T4 候选互斥），故替换之间无顺序偏移问题，本模块不做重叠防御。

- ❌ 被否：除 URL 外顺手"修"文本（给 HTML 补引号、规范化 alt）——4.7 明令「只替换 URL 部分」

### 2.2 输出顺序：按 `start` 降序（倒序）

PLAN 草案注释「调用方倒序应用，或整体一次 WorkspaceEdit」的落实：`buildReplacements` **直接返回降序**，调用方按序 splice 即无索引偏移；若走单次 `WorkspaceEdit`（T6 实际路线），多处编辑基于原文档区间解析，顺序无关。接口不变。返回顺序与 `refs` 输入顺序无关（内部排序）。

### 2.3 新 URL 的上下文安全化（本任务核心取舍）

上传响应解析出的 URL 可能含**裸 dest 不安全字符**：服务端文件名保留原名时（`uploadNameType=origin/default`），`abc_图 1.png`、`report (final).png` 都会进 URL（T2 `extractFileId` 解码后拼接，`customCdn + 文件ID` 同理）。直接裸写 `![a](https://x/abc_图 1.png)` 会把链接写坏（CommonMark 裸 dest 不允许空格——预览渲染为纯文本，**这是用正确数据写出坏文档**）。规则按上下文分两类：

| 上下文 | 规则 |
| --- | --- |
| markdown（`inline`/`refdef`） | URL 含裸 dest 不安全字符（空白、控制符、`(`、`)`、`\`、`<`、`>`）→ 整体包 `<>`（4.1 钦定的含空格写法，输出与输入对称）；包装内 `<`、`>`、`\`、控制符百分号编码（`<>` 定界与 `\` 转义敏感）。否则裸写 |
| HTML（`html`） | URL 中空白、控制符、`"`、`'`、`<`、`>` 百分号编码（空白**必须**编码：T4 §2.5 支持无引号属性值，空白会终结属性值；`ImageRef` 不带引号风格，无法只对无引号形态编码，故三种属性形态统一最严口径。`'` 编码防单引号属性同理）；其余原样 |

**markdown 侧 URL 文本一字不差**（除 `<`/`>`/`\`/控制符的百分号编码）：`abc_图 1.png` 在 markdown 里写成 `![](<https://x/abc_图 1.png>)`。HTML 侧空白百分号编码是唯一让步：`%20` 与裸空格语义等价（HTTP 客户端本就编码空格），而无引号属性值里的裸空格会写坏标签（`src=https://x/abc_图 1.png` 中 `1.png` 变成孤立属性）——「用正确数据写出坏文档」正是本节要防的事。

字符集合口径与 T4 扫描器终止类对齐（`src/parse.ts`）：markdown 裸 dest 遇 `[ \t\n]` 终止、HTML 无引号属性值遇 JS `\s`（含 NBSP 等）+ `` "'`=<> `` 终止——上表「空白/定界敏感」取两侧并集判不安全（markdown 命中即包 `<>`、HTML 命中即百分号编码），宁多勿漏；`=` 与 `` ` `` 亦属无引号终止类但不编码（浏览器宽容解析可恢复、MDX/JSX 要求引号值不会出现该形态），记 §6 残留边角。markdown 侧含 `(`、`)` 一律包装同为保守口径：不做括号平衡判定（转义混入时判定复杂），宁稳勿省。

- ❌ 被否：全量百分号编码后裸写（`abc_%E5%9B%BE%201.png`）——URL 文本被改写成难读形态，「回写 URL = customCdn + 文件ID / publicUrl / serverUrl + src」（4.3）的语义应保持原文；渲染等价但不符合"回写的就是拿到的链接"
- ❌ 被否：一律包 `<>`——安全 URL 无谓加噪音，且 `<img>` 的 HTML 上下文根本没有 `<>` 写法
- ❌ 被否：把 URL 提交前整体 `encodeURI`——会把 `?`/`#`/`&` 等结构性字符一并动掉或漏掉边角，两头不讨好
- ❌ 被否：引号感知（`ImageRef` 带引号风格、或 `buildReplacements` 收原文窥探 `text[urlStart-1]`，无引号形态把替换文本加引号）——可把让步缩到无引号形态、保住引号属性下的一字不差，但要动已冻结的 T4 接口或 PLAN 签名，收益只剩 `=`/反引号这类浏览器可恢复的边角（§6），不值

### 2.4 缺 key 跳过：失败项原文保留

`urlByKey` 中查不到 `key`、或对应 URL **trim 后为空**（空串/纯空白）→ 不产出该引用的替换——对应 4.4「失败的项保留原链接不动」：T6 只把上传成功的 `key → url` 放进 map，回写层零失败语义。URL 值派生自服务端响应（外部输入），空/空白 URL 写出去就是坏链接，这里是最后一道拦截。

## 3. 接口

```ts
// rewrite.ts（纯函数，不 import vscode）
export type Replacement = { start: number; end: number; text: string };

export function buildReplacements(
  refs: ImageRef[],
  urlByKey: Map<string, string>,
): Replacement[]; // 按 start 降序（§2.2，与输入顺序无关）；缺 key 或 URL 空白的引用跳过（§2.4）
```

与 PLAN §2 草案一致（类型与签名零变更）。内部 `markdownText(url)` / `htmlText(url)` 两个纯函数承载 §2.3 规则，不导出——测试经 `buildReplacements` 覆盖，避免为测试扩大导出面。

## 5. 测试方式

普通 mocha 断言（不 import vscode），fixture 手工构造 `ImageRef`（区间与 key 对齐 T4 产出形态）。核心断言方式：**把 `Replacement[]` 按返回顺序 splice 进原文**，与期望全文逐字对比——同时验证内容正确与倒序无偏移。

- **只换 URL、结构不动**：`![alt](./x.png "t")` → 替换后 `![alt](https://x/a.png "t")`（alt/title 原样）；尖括号 `<./x y.png>` 的区间含包装 → 整体换成裸安全 URL；`<img src="./x.png">` → 引号原样只换值；refdef `[r]: ./x.png "t"` → 只换定义处 URL，`![a][r]` 引用处不动。
- **倒序与多处**：3 个引用一次替换，按返回顺序 splice 全文正确（无索引漂移）；同 `key` 3 处 → 3 处同一 URL（验收 10 的回写侧）。
- **缺 key / 空 URL 跳过**：`urlByKey` 少一项 → 该项原文保留，其余正常（4.4）；URL 值为空串或纯空白 → 同样跳过（§2.4）。
- **安全化矩阵**：URL 含空格/括号 → markdown 包 `<>`（含 refdef）、URL 文本一字不差；同一 URL 在 html → 不包 `<>`、空白编码 `%20`；URL 含 `"`/`'` → html 侧 `%22`/`%27`；URL 含 `<`/`>`/`\` → markdown 包装内 `%3C`/`%3E`/`%5C`；安全 URL（`https://x/a.png`）→ 两种上下文均裸写原样。
- **无引号属性形态**：`<img src=./x.png>` + 含空格 URL → 值含 `%20`、属性结构完好（空白不得终结属性值，P0 场景）；单引号 `src='...'` 形态过同一矩阵。
- **解析往返**：`parseImageRefs` 产出的 refs（含 `<>` 包装、无引号 `src` 形态）直接喂 `buildReplacements`，splice 后与期望全文逐字对比——锁住与 T4 的区间口径契约（含 `<>` / 不含引号），防手工 fixture 与 T4 产出漂移。
- **乱序输入**：refs 打乱顺序传入 → 输出仍按 start 降序、全文正确。
- **空引用集 / 空 map**：返回空数组。

## 6. 边界说明

- URL 中的 `&` 若恰好构成 HTML/Markdown 实体形态（如 `&amp;`）会被渲染层解码，v1 不处理（文件名含实体字面量的概率趋近零）；查询串里的普通 `&` 不受影响（非实体形态不解码）。HTML 侧如需消灭该边角：`&` 写成 `&amp;` 即可（属性解析回来一字不差），代价是查询串 URL 全带视觉噪音、违「回写的就是拿到的链接」，v1 不做。
- 无引号属性值中的 `=`/反引号不编码：HTML5 语义下属 parse error 但浏览器宽容解析可恢复，MDX/JSX 本就要求引号值（无引号形态只出现在纯 HTML 场景）。残留边角接受；升级时机：严格解析器用户实遇时启用引号感知方案（§2.3 被否项）。
- 大小写、引号风格、title 格式一律保留原文（区间替换的自然结果）；html 引号字符不在区间内，永不触碰。
- 依赖 T4 的「区间互不重叠」与「`text.slice(urlStart, urlEnd) === rawUrl`」不变量，本模块不做防御性校验（单测以手工 fixture 对齐该形态）。
- URL 含换行/控制符（服务端畸形返回）→ markdown 侧包 `<>` 并百分号编码，HTML 侧编码；不会写坏文档结构。
- `decodeURIComponent` 造成的 URL 原文与磁盘文件名差异（T2 `extractFileId` 解码）不在本层修正：回写的是 URL，不是文件路径。
