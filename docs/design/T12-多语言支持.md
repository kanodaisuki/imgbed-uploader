# T12 方案设计：中英双语（i18n，英文默认）

- 状态：已冻结（2026-11-27 评审通过并实施完成，en/zh-cn 各 175 项全绿；意见已并入正文，见文末「变更记录」）；同日复审补漏已并入
- 对应任务：T12 多语言支持（新增任务；[`../plans/PLAN.md`](../plans/PLAN.md) 已冻结未登记，登记走 `decisions/` 或新版计划）
- 前置：无（独立改造，不依赖 T0~T11 未竟事项）
- 依据：VS Code 官方本地化机制（`vscode.l10n` + `package.nls*.json`）；[`../requirements/Requirement.md`](../requirements/Requirement.md) 无相关 FR，本文自定义验收

## 1. 目标与范围

**目标**：插件支持中英双语，**英文为默认语言**。VS Code 显示语言为 `zh-cn` 时全中文；其余一切语言环境显示英文。

**范围**（全部用户可见文本，约 90 条）：

| 区域 | 条数 | 现状 |
| --- | --- | --- |
| `package.json` 贡献点：`description`、5 条命令 title、13 项设置 description、`untrustedWorkspaces.description` | ~20 | 硬编码中文 |
| 代码内字符串：通知/按钮、InputBox 提示、Progress 文案、OutputChannel 报告行、DocumentPasteEdit 标题、错误消息 | ~70 | 硬编码中文字面量，散落调用点 |

**非目标**：

- README / 市场页面自动本地化（Marketplace 无此机制；根 README 已双语，不动）
- `zh-cn` 以外语种翻译（结构就绪后随时可加，见 §3 回退规则）
- 服务端返回的错误文本翻译（「服务端错误原样呈现」是既有承诺，不破）
- 测试用例名、代码注释、品牌名（`ImgBed Uploader`）翻译
- `package.json` `keywords` 本地化（评审裁决）：词条即 Marketplace 搜索索引，中英并存一数组已是两种语言的搜索全集，换 `%key%` 反有占位符裸露进索引的风险——S1 不动 :14–15
- 设置 `enum` 值（`authCode`、`telegram`、`default` 等）本地化：值即 `settings.json` 字面量，按技术名词不翻，`enumItemLabels` 不做；枚举语义仍在 description 里，随 S1 一起翻

## 2. 方案取舍

### 方案 A：官方 `vscode.l10n` + `package.nls*.json`（选定）

- manifest 字符串（命令 title、设置描述）用 `package.nls.json`（默认/英文）+ `package.nls.zh-cn.json`（中文），`package.json` 内换 `%key%` 占位符
- 代码字符串用 `vscode.l10n.t('English text', ...args)`，`package.json` 加 `"l10n": "./l10n"`，翻译文件 `l10n/bundle.l10n.zh-cn.json`；开发依赖 `@vscode/l10n-dev` 做字符串提取
- 优点：零运行时依赖（`vscode.l10n` 是 API 内建，1.73+，本插件最低 1.146 无兼容问题）；VS Code 按 `vscode.env.language` 自动加载；显示语言切换随 VS Code 重启生效、会话内 locale 恒定（§4 常量在模块加载期求值因此安全）
- 缺点：提取工具不识别模板字符串与动态 key——模板字符串由编码规约约束（§5-S2 规约 2）；动态 key 问题由下方补充裁决消除

### 方案 B：自建 `strings.ts` 常量字典（否决）

代码内可行，但 `package.json` 贡献点无法用常量本地化（必须 `package.nls` 机制），最终两套机制并存，比方案 A 更多代码。

### 方案 C：第三方 i18n 库（i18next 等）（否决）

为约 70 条字符串引入运行时依赖，且同样解决不了 manifest，纯增负。

### 补充裁决：`parse.ts` reason 本地化——code + 映射表（选定）

`parse.ts` 是纯函数模块（PLAN.md 约束不 import vscode），其 7 条 skipped `reason` 的本地化路线取舍：

| 路线 | 结论 |
| --- | --- |
| **code + 映射表（选定）**：`reason` 改稳定 code（`SkipReason` 联合类型），文案集中在 `strings.ts` 的 `REASON_TEXT` 映射（字面量过 `l10n.t`），`flow.ts` 编排边界映射为显示文本 | 提取工具自动抓取、零手工键；`Record<SkipReason, string>` 编译期保证每码必有译文；`parse.test.ts` 断 code 与语言无关 |
| 引入 `vscode.l10n` 进 parse.ts | 否决：破坏 PLAN.md 纯函数约定（改约定要走 `decisions/` 流程）；`reason` 变成随 locale 漂移的数据，parse 测试从测解析行为退化为测显示语言 |
| 动态 key 显示层包裹（`vscode.l10n.t(reason)` + 手工补键） | 否决：提取工具抓不到动态 key，手工键改名即静默失效；断言随语言漂移 |

## 3. 总体结构与回退规则

**新增文件**：

```
package.nls.json            # 英文（默认）：manifest 字符串
package.nls.zh-cn.json      # 中文：manifest 字符串（原文即现文案，零翻译成本）
l10n/bundle.l10n.json        # 英文（默认）：代码字符串（提取工具生成，入库作 L1 对照基准）
l10n/bundle.l10n.zh-cn.json  # 中文：代码字符串翻译（纯提取产物，无手工键）
src/strings.ts               # 按钮 label 常量（§4）+ REASON_TEXT 映射（§5-S2 规约 5）
```

**`package.json` 变更**：顶层加 `"l10n": "./l10n"`；`devDependencies` 加 `@vscode/l10n-dev`；`scripts` 加 `"l10n:extract": "vscode-l10n-dev export --outDir ./l10n ./src"`。

**回退规则**：`vscode.l10n.t('English text')` 在当前 locale 无对应键时原样返回源串。故英文默认**不需要**英文 bundle 参与运行，只需维护 `bundle.l10n.zh-cn.json`；`zh-tw`、`ja` 等一律回落英文。

**产物入库**：`bundle.l10n.json` 入库（L1 拿它与 zh-cn 对照，新增源串有 diff 可见）；若不入库，则 CI 需先跑 `pnpm run l10n:extract` 再跑 L1，二者取一，推荐入库。

> shortcut: 只做 zh-cn 翻译，zh-tw 等中文变体回落英文；要支持时复制 zh-cn 文件改差异词即可，升级时机：出现 zh-tw 用户反馈。

## 4. 关键前置：按钮 label 常量化（S0）

现状按钮「显示文案」与「点击分发」按字符串相等比较，共 10 处。翻译后文案一变，比较永不命中，**按钮动作静默失效（不报错）**——这是本改造最大风险点，必须最先处理：

| 文件 | 行 | 比较值 |
| --- | --- | --- |
| `src/ui.ts` | 17 | `'打开设置'` |
| `src/ui.ts` | 31 | `'设置认证信息'` |
| `src/ui.ts` | 82 | `'重试失败项'` |
| `src/ui.ts` | 84 | `'重新设置认证信息'` |
| `src/commands.ts` | 45 | `'复制链接'` |
| `src/commands.ts` | 73 | `'重新测试'` |
| `src/commands.ts` | 75 | `'重新设置认证信息'` |
| `src/commands.ts` | 77 | `'打开设置'` |
| `src/paste.ts` | 166 | `'打开设置'` |
| `src/paste.ts` | 171 | `'设置认证信息'` |

做法：新增 `src/strings.ts` 导出按钮 label 常量（`l10n.t` 结果；locale 会话内不变，模块加载期求值一次即可），显示与比较共用同一常量：

```ts
// src/strings.ts
import * as vscode from 'vscode';

export const BTN = {
  openSettings: vscode.l10n.t('Open Settings'),
  setCredentials: vscode.l10n.t('Set Credentials'),
  resetCredentials: vscode.l10n.t('Update credentials'),
  retryFailed: vscode.l10n.t('Retry failed items'),
  copyLink: vscode.l10n.t('Copy link'),
  retest: vscode.l10n.t('Test again'),
} as const;
```

调用点形态（示例）：

```ts
const action = await vscode.window.showWarningMessage(msg, BTN.openSettings);
if (action === BTN.openSettings) { ... }
```

被否备选：`MessageItem` 加自定义 `id` 按引用/`id` 分发——更「正统」，但要改 `showXMessage` 的重载用法与返回类型断言，改动面更大；常量方案与现状代码形态最贴。

编码规约（强制）：

1. **源串即英文**：`l10n.t('Upload all local images in the document')`，中文进 `bundle.l10n.zh-cn.json`。
2. **带变量用占位符**：`l10n.t('Uploading images ({0} items)', n)`；**禁止模板字符串直接进 `l10n.t`**（提取工具无法处理）；**禁止名词碎片拼句**——`paste.ts:158` 的 `未配置${missing}`（「图床地址」/「认证信息」碎片）、`client.ts:238` 多插槽长句这类形态，碎片直译塞回句槽在英文里语序不成立，改整句两态或完整从句占位。
3. **服务端文本不翻，本地后缀翻**：如 `'Invalid auth code' + '（请检查认证信息）'` 的组合形态改为 `serverText + vscode.l10n.t(' (check your credentials)')`；服务端部分保持原样（与「服务端错误原样呈现」一致）。
4. **品牌与专有名词不翻**：`ImgBed Uploader`、`paste-*` 文件名、`serverUrl` 等设置键名。
5. **`parse.ts` reason 走 code + 映射表**（§2 补充裁决）：纯函数模块不 import vscode（PLAN.md 既有约束），7 条 `reason` 由显示文本改为稳定 code，文案集中在 `strings.ts` 映射；`flow.ts` 编排边界把 code 转显示文本后，`skipped` 等结构体字段保持显示文本语义不变：

   ```ts
   // parse.ts：reason 收紧为联合类型（纯度保持）
   export type SkipReason =
     | 'unclosedAngleUrl' | 'illegalResidue' | 'unwrappedSpace'
     | 'protocolRelative' | 'unparsableUrl' | 'emptySrcAttr' | 'unclosedParen';

   // strings.ts：字面量过 l10n.t，提取工具自动抓取，零手工键
   export const REASON_TEXT: Record<SkipReason, string> = {
     unclosedAngleUrl: vscode.l10n.t('Unclosed angle-bracket URL'),
     // ...
   };

   // flow.ts：编排边界映射（flow 本就 import vscode）；句子骨架同样走 l10n 占位句，
   // 「跳过：」等骨架不得写死中文（否则英文界面中英混排，违反验收 2）
   details.push(vscode.l10n.t('Skipped: {0} — {1}', s.key, REASON_TEXT[skip.reason]));
   ```

   `flow.ts` 自产的跳过原因（`命中白名单跳过` 等）不走 code，直接 `l10n.t` 字面量。报告行骨架（`flow.ts:406/:409/:413/:417/:421/:553`）全部改 `l10n.t` 占位句，其中 :406 的嵌套模板 `（回写 ${n} 处）` 拍平成一个 `{0}{1}{2}` 单句（规约 2）。`client.ts` / `download.ts` / `secrets.ts` 在消息产生处直接 `l10n.t`；client/download 需补 `import vscode`——两模块原按 T2/T10 设计定为非 vscode 层（T10：「download.ts：不 import vscode」，与 client.ts 同层；PLAN.md 的纯函数标记仅 parse/rewrite），此约定下调随本任务登记 `decisions/`。`secrets.ts` 已 import vscode，无此问题。
6. `rewrite.ts`、`extension.ts`、`config.ts` 无用户可见字符串，不动。

收口与注意：

- **grep 收口**：S2 完成后 `src/*.ts`（注释除外）grep 中文归零、逐条销账后再进 S3——「漏包 l10n.t」是人工清点唯一的系统性漏洞，L1 有自动化扫描兜底（§5-S4）

**L1 翻译完整性测试（0.25d，新增）**：纯 Node 测试进现有套件：`package.nls.json`/`package.nls.zh-cn.json` 与 `bundle.l10n.json`/`bundle.l10n.zh-cn.json` 键一一对应、无空值、`{0}` 占位符编号集合逐键一致（`{0}{2}` 与 `{0}{1}` 个数相同也判错）。reason 重构后提取产物全覆盖，**无例外键**。覆盖「漏键 → 中英混排」风险，成本≈0，必做。

另加两条守卫（键对齐抓不住的两类事故）：

- **`%key%` 双向校验**：`package.json` 每个 `%key%` 在两份 nls 均可解析，反向报告 nls 死键——漏键会裸露 `%key%`，比中英混排更糟
- **源码裸中文扫描**：`src/*.ts`（注释、测试除外）与 `package.json`（`keywords` 除外）无中文裸串——防「漏包 l10n.t」：漏包在 en 界面出中文而键对齐全绿，是 S2 grep 收口的机械兜底

**L2 双 locale 全量测试（~0.75d，新增）**：中英都跑全套自动化：
