## 2. 方案与取舍

### 2.1 解析策略：单遍扫描 + 共用「目的地子程序」，零依赖

三类候选（行内/引用式、引用定义、`<img>`）共用同一个 dest 解析子程序（title 剥离、`<>`、清洗、分类、decode，见 §2.3；HTML 候选跳过 title/`<>` 步、清洗改实体解码，见 §2.5）；扫描器只需解决三件事：跳过代码区（§2.2）、配对括号（alt 与 dest 的平衡扫描，`\x` 转义不计深度）、定位 URL 区间。约 300 行，全部可单测。

- ❌ 被否：现成 Markdown 解析器（remark / mdast）——新增多个依赖违背 PLAN 依赖策略；且 mdast 节点位置覆盖整个 `![...]()` 语法，**不给 URL 子串偏移**，回写区间仍要在节点内二次定位（等于还要写 §2.3）；MDX 的 JSX 语法差异还要另配解析模式
- ❌ 被否：纯正则多模式——嵌套括号（`p(1).png`）、转义、alt 内含 `[]`、title 三形式与 dest 的组合爆炸，边界处极易**误改文本**（PLAN 风险表最忌）

### 2.2 代码区识别：预计算「代码区间」，候选落区内一律不产出

先遍一遍文本算出全部代码区间（`[start, end)`），扫描候选时查区间：

- 围栏代码块：``` / `~~~` 起止配对（起始行可带 info string；闭合围栏须同字符、**长度 ≥ 开启围栏**且不带 info string——```` 可关 ```）；未闭合围栏延伸到文档末尾
- 行内代码：反引号组等长配对（允许跨行，CommonMark 允许多行 code span），**仅在围栏与缩进代码区之外的文本中配对**——否则缩进代码里的孤立反引号会和正文配对、code span 吞掉正文图片
- 缩进代码块：≥4 空格或 Tab 开头、且非段落懒延续（上一非空行为段落文本则视为延续）、列表行（`- `/`* `/`1.` 等）中断代码——CommonMark 近似规则
- 区间互不吞并，**计算次序：围栏 → 缩进代码（纯行级判定，不看行内语法）→ 行内代码（仅剩余文本中配对）**——围栏/缩进代码内孤立反引号是内容，不开 span；缩进代码不吞缩进 ≤3 空格的围栏行

**宁漏勿错**：近似规则在列表嵌套深处的缩进内容上可能误判为代码 → 少数图片漏识别（进不了回写），但**绝不误改代码样例文本**。与 PLAN 风险表「可疑处跳过，绝不误改文本」一致。

### 2.3 dest 子程序：title 剥离 → `<>` → 清洗 → 分类 → decode 容错

对候选的 URL 原文区间（含 `<>`，PLAN §2 口径）：

1. **`<>` 包裹**：`<` 起、`>` 止（`<>` 内允许空格），path 取内部；`<` 无闭合 → 可疑跳过。`<>` 后允许再跟 title（CommonMark `![a](<p> "t")`），非法残留 → 可疑跳过。
2. **裸路径**：到第一个未转义空白为止；其后残留必须是合法 title（`"..."`/`'...'`/`(...)`，完整收尾）否则**整个候选可疑跳过**——裸空格路径 `![a](my file.png)` 按 CommonMark 就不是链接（预览渲染为原文），严格处理与渲染行为一致，且用户能从失败报告看到它被跳过了。❌ 被否：宽松取到右括号——会把非链接文本改写成新 URL，属误改。
3. **清洗**：markdown 候选做反转义（`\(` → `(` 等 CommonMark 标点集）；HTML 候选做实体解码（`&amp;`/`&lt;`/`&gt;`/`&quot;`/`&#39;` + 数字实体最小集）——**互不做对方的清洗**（HTML 属性里 `\(` 是字面两字符，反转义即误改）。
4. **分类**：先排除 Windows 盘符 `^[A-Za-z]:[\\/]`，再看 scheme——`http(s):` → remote；Windows 盘符或无 scheme（相对/绝对路径）→ local；`data:` 及其它 scheme → 静默跳过；`//` 开头的协议相对 URL → 可疑跳过（§2.6/§6）。
5. **截断与 decode 容错（仅 local）**：先截掉 `?`/`#` 及其后内容（query/fragment 对本地文件无意义；VS Code 预览解析本地路径同样截断——`?v=1` 缓存穿透写法照常显示即证），再 `decodeURIComponent` **失败保留原值继续，不抛异常**（4.1）→ 得 `target.path`。**remote 不做 URI decode**：`%2F`/`%3A` 是语义性编码，decode 会把两个不同 URL 错并成同一 `key`（误合并与 §6 大小写条目同忌）；`target.url` = 反转义后的原文 URL。
6. **key**：local 对截断 + decode 后的路径做**文档内词法规范化**（`\`→`/`、去 `./`、折叠 `//`、消解 `.`/`..`；**前导 `//` 不折叠**——UNC `\\server\share\x.png` 归一为 `//server/...`，不与相对路径 `server/...` 误合并）——`./img/a.png`、`img/a.png`、`img/./a.png` 同键（4.6 去重即验收 10）；remote = 未 decode 的完整 URL。不做大小写归一（大小写敏感文件系统存在，边界见 §6）。
7. **空路径**（`![]()`、`![](<>)`、`src=""`、`#anchor` 类截断后为空）：静默跳过（合法语法但无目标，非可疑）。

### 2.4 引用式：定义仅在被 ≥1 个**图片式**引用使用时产出

`[ref]: path title` 定义可能被普通链接使用（`[文字][ref]`）——若仅凭扩展名粗筛就把 `[ref]: ./shot.png` 当图片上传并回写，会**改掉普通链接的目标**（误改）。故：

- 先全量收集定义（label 归一：trim + 内部空白折叠 + 小写，CommonMark 匹配语义；重复 label **首个生效**）；
- 扫描图片式使用（`![alt][label]`、`![label][]`、`![label]` 三种形态）建立 used 集合；
- 仅 used 的定义产出 `kind: 'refdef'`，URL 区间落在**定义行**（4.7「替换定义处的 URL」）；引用处 `![...]` 本身不产出区间。
- FR-2 选区归属不能只看 URL 区间：refdef 的 URL 区间在定义行，用户选中 `![a][r]` 时按「urlStart ∈ 选区」过滤会漏判成「选区无图像引用」。故 refdef 条目随带**全部图片式引用区间** `useSpans`（升序，区间口径为 `![` 起至引用语法闭合 `]` 止；§3），T6 判「选区命中任一 useSpan」——选中第 2 个及以后的 `![a][r]` 同样命中（仅带首个区间会漏判）。
- ❌ 被否：不做 used 判定、仅凭扩展名认定义——普通链接指向图片文件时误改链接。

附带效应（符合 4.7「只替换 URL」）：定义若同时被图片和普通链接使用，回写后链接目标同步变为远程地址——语义一致（本地文件已传走），§6 记为已知行为。

### 2.5 HTML `<img>`：仅字面 `src` 值

`<img`（大小写不敏感）后解析属性（属性间空白含换行，HTML 标签可跨行），取第一个**字面** `src` 值——属性名精确匹配（`src` 后随空白或 `=`；`data-src`/`x-src` 不命中）；取值双引号 / 单引号 / 无引号裸值（HTML5 规则：不含空白与 `"'=<>`）。URL 区间为**引号内的值**（引号是属性语法，不含在区间内，与 markdown `<>` 计入口径的差异见 §3 注）。

- `src={expr}`（JSX 表达式）→ 静默跳过（非字面路径，无可上传目标）；`src` 无值 → 可疑跳过
- `srcset` 不处理（v1 边界，§6）；`<image>`/其它标签不认

### 2.6 可疑条目随结果返回（`ParseResult`）

PLAN 风险表对策是「可疑处跳过**并列入失败报告**」，`ImageRef[]` 单返回值带不出跳过信息，故返回值改 `ParseResult`（偏差登记 PLAN「变更记录」）。可疑的定义收窄为：**形似图像语法但无法安全定位 URL 区间、或无法安全归类**（裸空格 dest、`<>` 未闭合、dest 非法残留、`src` 无值、引用定义的 dest 解析失败、协议相对 URL）——纯文本中的 `![wow]`（无定义）不是可疑，就是普通文本，避免报告噪音。跳过即不产出区间，**宁漏勿改**。

### 2.7 `target` / `key` 字段口径（对 PLAN §2 草案的落实与微调）

- local：`target.path` = 清洗后路径（保留文档相对形态，解析归 T6 的 4.8）；`key` = 词法规范化路径。PLAN 草案写「规范化绝对路径」，但 `parseImageRefs(text)` 无文档目录可依，且去重是**文档内**行为（4.6），词法规范化已覆盖全部同文件异写法；绝对路径解析由 T6 按 4.8 做。
- remote：`target` 补 `url` 字段（完整 URL，FR-5 下载与去重都要用；PLAN 草案只有 `host`）；`host` = `new URL(url).hostname`（5.4 白名单按 hostname 精确匹配）；`key` = 完整 URL（反转义后、**未 URI-decode** 的原文，§2.3 步骤 5）。
- `rawUrl` / 区间：`[urlStart, urlEnd)` 覆盖原始 URL 文本**含 `<>` 包装**（替换时连包装一起换，T5 直接写新 URL 即可）；HTML 属性值不含引号（引号是属性语法，替换时引号保留）。

## 3. 接口

```ts
// parse.ts（纯函数，不 import vscode）
export type ImageRef = {
  kind: 'inline' | 'refdef' | 'html';
  urlStart: number;   // URL 部分（含 <> 包装）在文档文本中的偏移
  urlEnd: number;     // [urlStart, urlEnd) 保证 text.slice() === rawUrl（测试黄金断言）
  rawUrl: string;
  target:
    | { type: 'local'; path: string }                                  // 已清洗：剥 <>、剥 title、反转义、截 `?`/`#`、decode
    | { type: 'remote'; url: string; host: string };                   // host = hostname（5.4）
  key: string;        // 去重键：local=词法规范化路径，remote=未 decode 完整 URL（§2.7）
  useSpans?: { start: number; end: number }[]; // refdef 专用：全部图片式引用区间（FR-2 选区归属，§2.4；inline/html 不带，选区归属按 [urlStart, urlEnd) 判）
};

export type Skipped = { start: number; end: number; reason: string };  // 可疑跳过，reason 简体中文进失败报告

export type ParseResult = { refs: ImageRef[]; skipped: Skipped[] };    // refs 按 urlStart 升序，skipped 按 start 升序

export function parseImageRefs(text: string): ParseResult;
```

较 PLAN §2 草案的偏差（均登记 PLAN「变更记录」）：返回值改 `ParseResult`（§2.6）、`key` 语义改词法规范化（§2.7）、remote target 补 `url`（§2.7）、refdef 补 `useSpans`（§2.4，FR-2 选区归属）。扩展名粗筛常量 `png/jpg/jpeg/gif/webp/avif/svg/bmp/ico`（4.1）内聚在 `parse.ts`，对 local 最终 `path`（已截断 query/fragment，§2.3 步 5）做后缀判断、大小写不敏感；**仅作用于 local**（remote 不做粗筛：徽章图等无扩展名仍要转存，FR-5；远程 `.pdf` 在转存开启时尝试下载、由「非图片内容」失败兜底）。

## 5. 测试方式

普通 mocha 断言（测试跑在 vscode-test 宿主里但**不 import vscode**），纯函数直接喂文本。每条用例统一断言**回写区间黄金不变量**：`text.slice(ref.urlStart, ref.urlEnd) === ref.rawUrl`（T5 的生命线，凡产出必查）。

- **行内式矩阵**：`![a](./x.png)`；title 三形式（`"..."`/`'...'`/`(...)`）剥离且区间不含 title；尖括号 `<./x y.png>`（含空格、含 `>` 转义场景）；`%20` 等编码 decode、**decode 失败保留原值**（`%ZZ` 类）；嵌套括号 `![a](p(1).png)`；转义 `\(` 不闭合 dest；alt 含 `[]` 转义与嵌套；链接内嵌图片 `[![a](./x.png)](https://…)`；`![]()`/`![](<>)` 空目标跳过；`./a.png?raw=1` 粗筛命中且 `target.path`/`key` 截断 query 与 `./a.png` 相同；Windows 盘符 `C:/img/a.png`、`C:\img\a.png` 判 local 不落 scheme 跳过。
- **引用式矩阵**：`![a][r]`、`![r][]`、`![r]` 三形态；`[r]: ./x.png "t"` 产出在定义行；label 大小写/空白折叠匹配；重复 label 首个生效；**def 仅被普通链接使用 → 不产出**；def 未被使用 → 不产出；图片 + 链接共用 def → 产出；多处图片引用共用 def → `useSpans` 覆盖全部引用区间（含第 2 个及以后）。
- **HTML 矩阵**：双引号 / 单引号 / 无引号 `src`；大小写 `<IMG SRC>`；多属性且 `src` 在任意位置；属性跨行（`<img` 换行后 `src=...`）；`data-src`/`x-src` 不命中；`src="a&amp;b.png"` 实体解码为 `a&b.png`；`src={expr}` 跳过；`src` 无值 → skipped。
- **代码区矩阵**：``` 围栏内、`~~~` 围栏内、行内代码内、缩进代码块内、围栏起始行 info string 含 `![...]` 伪候选——全部不产出；正文对照组正常产出。另测：```` 长围栏闭合 ```、未闭合围栏延伸到文档末尾、围栏内孤立反引号不开 code span。
- **粗筛与 remote**：local `.pdf` 不产出、`.PNG` 大写产出、无扩展名 local 不产出；remote 无扩展名（徽章 URL）产出且 `host`/`key` 正确；remote 不 decode——`https://x/a%2Fb.png` 与 `https://x/a/b.png` → `key` 不同；`data:` URI 跳过。
- **可疑条目**：`![a](my file.png)`、`![a](<p.png"`、dest 非法残留、`![](//host/a.png)` 协议相对 URL → `skipped` 有条目且 `refs` 无产出、区间定位合理。
- **去重键**：`./img/a.png` / `img/a.png` / `img/./a.png` / 反斜杠写法 → `key` 相同；`../a.png` 与 `a.png` → 不同；UNC `\\server\share\a.png` → `//server/share/a.png`，与相对 `server/share/a.png` 不同键。

## 6. 边界说明

- **HTML 块内的 markdown 图片语法**（`<div>` 块中出现 `![a](./x.png)`）按 CommonMark 是原文非图片，v1 照样识别并可能改写其 URL 文本——已知限制，接受（真实文档罕见；改写仅限 URL 文本本身，不动结构）。
- 缩进代码块识别是 CommonMark 近似（§2.2）：列表嵌套深处的缩进图片可能被误判进代码区而漏识别；方向是宁漏勿错。
- 引用定义仅支持单行（dest 与 title 各占一行的 CommonMark 写法不支持）；多行 code span 跨行配对支持（§2.2），但内容仍按代码区跳过。
- `srcset` 不处理：`<img srcset="...">` 无 `src` 时该图不产出（手工处理，v1 不做首图猜测）。
- 大小写不参与去重归一（Windows 大小写不敏感下 `A.png`/`a.png` 可能同文件，v1 不合并——宁可重复上传一次，不可误合并两个不同文件）。
- 定义被图片与普通链接共用时，回写影响链接目标（§2.4）；decode 失败保留原值继续（4.1）；`data:` 与非 http(s) scheme 一律跳过。
- 极端边界（`>` 出现在裸路径、`(?...)` 语法糖等）一律可疑跳过不猜测：解析器唯一红线是**绝不产出错误区间**——错误区间 = 误改文本。
- HTML 注释 `<!-- <img src="x.png"> -->` 中的 `<img>` v1 照常识别并只改写 URL 文本（罕见，与 HTML 块内 markdown 语法同口径）。
- 协议相对 URL（`//host/a.png`）v1 可疑跳过：无 scheme，FR-5 下载与 host 白名单匹配都需绝对 URL，不猜测协议；升级时机：确有用户遇到时按 https 解释。
